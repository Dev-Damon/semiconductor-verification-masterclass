Part 5 · 칩을 깨우다

SoC Booting Flow
전원을 켜면, 칩은 어떻게 깨어나는가

전원 버튼 한 번 → 첫 명령어 fetch → OS 진입. 그 사이에 칩이 스스로를 깨우는 정교한 순서가 있습니다. 이 순서를 알면 "부팅 검증" 면접 질문이 쉬워집니다.

왜 배우나 · 한 문장 정의

부팅 = 칩이 "스스로를 부팅 가능한 상태로" 끌어올리는 사다리

전원이 인가된 직후의 SoC는 아무것도 모르는 상태입니다. 클럭도 불안정하고, DRAM도 비어 있고, OS는 어디 있는지도 모릅니다.

Booting Flow란 이 깜깜한 상태에서 OS가 돌 수 있는 상태까지, 정해진 순서로 한 단계씩 올라가는 과정입니다. 검증 엔지니어는 이 순서가 실리콘에서 정확히 그대로 일어나는지를 시뮬/에뮬에서 미리 증명해야 합니다.

PORPLL lockreset vector BootROMBootloader (SPL / U-Boot)DRAM init Secure BootChain of Trust
한 번 잘못 부팅되는 칩은 벽돌(brick)이 됩니다 — 그래서 부팅은 가장 먼저, 가장 철저히 검증하는 시나리오 중 하나입니다.
직관적으로 이해하기

부팅 체인 = 사람이 아침에 깨어나 출근하는 순서

사람이 아침에 깨는 순서로 생각하면 한 번에 외워집니다.

  • 눈을 뜬다 → POR (전원 인가·리셋)
  • 정신을 차린다 → 클럭/PLL 안정(lock)
  • 몸이 자동으로 하는 기본 행동 → BootROM
  • 씻고 옷 입기 → 부트로더 · DRAM 초기화
  • 집을 나서 출근 → OS 진입

한 단계가 다음 단계를 깨우는 릴레이 계주를 떠올려도 좋습니다.

  • 가장 단순한 첫 주자 → BootROM (칩에 새겨진 마스크 ROM)
  • 바통을 받아 다음을 준비 → SPL (작은 2차 부트)
  • 본격적으로 달리는 주자 → U-Boot (메인 부트로더)
  • 결승선 → OS / 펌웨어 진입

핵심: 작은 부트 코드가 더 큰 부트 코드를 불러오는 릴레이. 각 단계는 "다음 단계를 메모리에 올리고 그곳으로 넘긴다"가 전부입니다.

단계 ①②③ · 하드웨어가 칩을 깨운다

POR · PLL lock · reset 해제 — 정신을 차리는 시간

⚡ POR (Power-On Reset)

전원 전압이 안정 범위에 들어올 때까지 모든 회로를 강제로 리셋 상태에 묶어두는 신호입니다. 전압이 출렁이는 동안 회로가 엉뚱하게 움직이지 못하게 막는 안전장치.

실험 장비를 켜기 전, 모든 다이얼을 0점에 맞춰 놓고 시작하는 것과 같은 개념 — 단, 전기적으로 한순간에.

🔄 PLL lock

칩 내부 고속 클럭은 외부의 느린 기준 클럭을 PLL(Phase-Locked Loop)로 곱해서 만듭니다. 만든 직후엔 주파수가 흔들리며, 안정되면 lock 신호가 뜹니다.

lock 전에 reset을 풀면 CPU가 불안정한 클럭으로 동작 → 랜덤하게 죽습니다. 그래서 lock을 기다리는 것이 결정적입니다.

순서가 핵심: 전압 안정 → PLL lock → reset 해제. 이 순서가 깨지면 칩은 결코 안정적으로 깨어나지 못합니다.
단계 ④⑤ · 코드가 시작되는 지점

reset vector에서 첫 명령을 집어, BootROM을 연다

reset vector = reset이 풀린 CPU가 가장 먼저 명령어를 읽으러 가는 고정된 주소입니다. 하드웨어로 박혀 있어 항상 같은 곳을 봅니다.

그 주소가 가리키는 곳에 BootROM이 있습니다 — 칩 제조 시 새겨 넣어 절대 바꿀 수 없는 마스크 ROM. 여기 담긴 1차 부트 코드가 칩의 "타고난 본능"입니다.

  • BootROM이 하는 일: 기본 하드웨어 셋업, 부팅 매체(eMMC·UFS·NAND·USB) 선택
  • 스토리지에서 다음 부트로더(SPL)를 내부 SRAM으로 읽어옴
  • 읽어온 코드의 서명을 검증한 뒤 점프 (Secure Boot)
// reset vector = 전원 켤 때마다
// CPU가 무조건 점프하는 고정 주소
#define RESET_VECTOR  0x00000000   // 예시값 — 실제 주소는 칩/아키텍처마다 다름(ARMv8은 RVBAR가 결정, 흔히 BootROM 베이스)

// 그 주소엔 BootROM이 매핑됨 (읽기전용)
void bootrom_main() {
  setup_basic_clocks();
  dev = select_boot_device();   // eMMC? USB?
  spl = load_from(dev, SPL_ADDR);
  if (!verify_signature(spl))   // 보안!
    hang();                       // 실패 → 정지
  jump_to(spl);                   // 2차 부트로 점프
}

reset vector는 "전원을 켜면 무조건 여기서부터 시작한다"는 출발선이 칩에 영구히 새겨져 있는 것입니다. 매번 같은 곳에서 시작하기에, 부팅이 항상 같은 방식으로 재현됩니다.

단계 ⑦⑧⑨ · 점점 큰 코드를 불러온다

SPL → DRAM 초기화 → U-Boot, 그리고 OS

왜 부트로더가 여러 단계(SPL → U-Boot)일까요? 답은 메모리입니다. 처음엔 큰 DRAM이 아직 켜지지 않아, 칩 내부의 작은 SRAM에 들어갈 만큼 작은 코드(SPL)만 돌릴 수 있습니다.

🧠 왜 DRAM init이 큰 일인가

DRAM은 그냥 켠다고 동작하지 않습니다. 타이밍 파라미터 설정·트레이닝(전기 신호 보정)을 거쳐야 안정적으로 읽고 쓸 수 있습니다. 이게 SPL의 핵심 임무이자 부팅 디버깅의 단골 실패 지점입니다.

🪜 왜 두 단계로 나누나

SPL은 좁은 SRAM에 겨우 들어가는 최소한의 코드로, 큰 DRAM을 켜는 일만 합니다. DRAM이 켜진 뒤에야 비로소 풍부한 기능을 가진 U-Boot를 그 넓은 DRAM에 올려 돌릴 수 있습니다. 좁은 발판을 딛고 넓은 무대로 올라서는 사다리 구조입니다.

보안 · Secure Boot

Chain of Trust — 신뢰의 사슬을 한 칸씩 잇는다

Secure Boot의 핵심: 각 단계가 다음 단계로 점프하기 전에, 그 코드의 디지털 서명을 검증합니다. 검증에 실패하면 부팅을 멈춥니다. 변조된 펌웨어가 끼어들 틈을 막는 것이죠.

Root of Trust는 절대 변조 불가한 BootROM + 칩에 구운 eFuse 키입니다. 여기서 출발한 신뢰가 한 칸씩 다음 단계로 전달됩니다 — 한 칸이라도 검증 실패하면 사슬이 끊겨 부팅 중단.

일상의 비유: 봉랍 인장으로 봉인된 공문서가 한 사람에서 다음 사람으로 전달되는 것과 같습니다. 받는 사람은 인장이 진짜인지 확인한 뒤에만 봉투를 열고, 그 안의 문서가 다시 다음 사람의 인장을 검증합니다 — 가장 믿을 수 있는 첫 인장(Root of Trust)에서 시작된 신뢰가 한 칸씩 이어집니다.

검증 엔지니어의 일

부팅을 어떻게 검증하나 — 실리콘 전에 미리 돌려본다

칩은 만든 뒤 못 고칩니다. 그래서 부팅 시퀀스를 실물 칩이 나오기 전에 시뮬레이션과 에뮬레이션 위에서 끝까지 돌려봐야 합니다.

🧪 무엇을 확인하나

  • reset 해제 타이밍 — PLL lock 이후에 풀리는가
  • CPU가 정확히 reset vector에서 첫 fetch 하는가
  • BootROM → SPL → U-Boot 점프 순서가 맞는가
  • DRAM init이 성공하고 메모리 read/write가 되는가
  • 서명 위·변조 시 부팅이 정상적으로 거부되는가

🛠️ 어떻게 (C-test)

실제 부트 코드(또는 축약판)를 C로 짠 테스트(C-test)로 만들어, CPU 모델 위에서 실행시킵니다. (Part 2-2의 그 기법!)

  • RTL 시뮬: 정확하지만 느림 → 초기 단계만
  • 에뮬레이션: 빠름 → OS 부팅까지 통째로 돌림
  • 파형·레지스터 로그로 어느 단계에서 멈췄는지 추적

부팅 검증의 목표는 단순합니다: "실리콘이 나오기 전에, 칩이 OS까지 깨어나는 걸 한 번이라도 본다." 이게 안 되면 그 칩은 켜자마자 벽돌입니다.

면접 예상 질문

이렇게 물어보면, 이렇게 답한다

reset vector가 뭔가요?
reset이 해제된 CPU가 가장 먼저 명령어를 fetch하는 고정 주소입니다. 하드웨어로 정해져 있어 전원을 켤 때마다 항상 같은 곳에서 실행을 시작하며, 보통 그 주소에 BootROM이 매핑되어 1차 부트 코드가 실행됩니다.
BootROM의 역할과 PLL lock이 왜 중요한가요?
BootROM은 칩에 새겨진 변경 불가한 마스크 ROM으로, 기본 하드웨어 셋업과 부팅 매체 선택, 다음 부트로더(SPL)를 SRAM에 로드하고 서명을 검증하는 1차 부트 코드입니다. PLL lock은 내부 고속 클럭이 안정됐다는 신호인데, lock 전에 reset을 풀면 CPU가 불안정한 클럭으로 동작해 무작위로 죽기 때문에, reset 해제 전 반드시 lock을 기다려야 합니다.
Secure Boot / Chain of Trust를 설명하고, 부팅을 어떻게 검증하나요?
각 부트 단계가 다음 단계 코드의 서명을 검증한 뒤에만 실행을 넘기는 구조입니다. 변경 불가한 BootROM과 eFuse 키가 Root of Trust가 되고, 신뢰가 SPL→U-Boot→OS로 사슬처럼 이어지며, 한 단계라도 검증 실패 시 부팅을 멈춥니다. 검증은 실리콘 전에 부트 시퀀스를 C-test로 만들어 RTL 시뮬·에뮬레이션에서 돌려, reset 타이밍·reset vector fetch·DRAM init·서명 거부 동작까지 끝까지 확인합니다.
핵심 요약

이 챕터, 한 손에 잡기

  • POR → PLL lock → reset 해제: 하드웨어가 칩을 깨우는 순서
  • CPU는 reset vector(고정 주소)에서 첫 명령 fetch
  • BootROM(변경 불가 마스크롬) = 1차 부트, SPL을 로드
  • SPL → DRAM init → U-Boot → OS: 작은 코드가 큰 코드를 부르는 릴레이
  • Secure Boot = 단계마다 서명 검증, Root of Trust부터 이어진 사슬
  • 검증: 부트 시퀀스를 C-test로 시뮬/에뮬에서 OS까지 돌려본다

"SoC 부팅은 POR·PLL lock 후 CPU가 reset vector에서 깨어나 BootROM→부트로더→OS로 신뢰의 사슬을 이으며 올라가는 과정이고, 저는 그 시퀀스를 실리콘 전에 C-test로 검증합니다."

— 작은 부트 코드가 더 큰 코드를 차례로 불러오는 릴레이라고 말하면 면접관이 바로 끄덕입니다.
