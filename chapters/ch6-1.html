JTAG = 핀 몇 개로 칩 내부에 접근하는 표준 뒷문

JTAG(IEEE 1149.1)은 칩 외부에서 핀 4개(+1)로 내부 회로에 접근하는 산업 표준 인터페이스입니다. 원래는 보드 검사용이었지만, 지금은 디버깅·프로그래밍·테스트 제어의 만능 통로가 되었습니다.

🚪 왜 필요한가

  • 칩은 패키징되면 내부 신호선에 오실로스코프를 못 댐
  • 핀 수백 개를 일일이 빼서 검사하면 비용·면적 폭발
  • 그래서 최소 핀으로 내부 전체에 닿는 통로가 필요

🧰 무엇에 쓰나

  • 테스트: 보드 위 납땜·핀 연결 검사(boundary scan)
  • 프로그래밍: 플래시·FPGA 비트스트림 굽기
  • 디버깅: CPU 멈춤/레지스터 읽기(gdb + JTAG)
큰 그림: JTAG는 DFT(Design for Test)의 대표 인터페이스입니다. DFT란 "칩을 만들 때부터 나중에 테스트하기 쉽게 회로를 미리 설계해 넣는 것" — JTAG는 그 표준 출입구입니다.
개발자 직관으로 번역

이미 당신은 JTAG를 매일 쓰고 있다

실행 중인 프로세스에 gdb -p 로 붙어 멈추고, 변수를 들여다보고, 메모리를 읽어본 적 있죠? JTAG는 실리콘 위에서 도는 칩에 gdb로 붙는 것과 똑같습니다. 디버거(OpenOCD 등)가 JTAG 포트로 CPU를 halt하고 레지스터를 읽습니다.

또는 서버 뒤에 몰래 달려 있는 직렬 콘솔 / 관리용 백도어 API를 떠올리세요. 평소 앱은 안 쓰지만, 장애가 나면 그 포트로 들어가 모든 상태를 들여다보고 조작합니다. JTAG가 정확히 그 역할입니다.

건물로 비유하면 점검용 비상계단 + 마스터키입니다. 평소 입주민(정상 동작)은 안 쓰지만, 점검·정비 때는 그 계단으로 모든 층의 모든 방에 들어갈 수 있죠.

강력하기에 양날의 검입니다 — 그래서 양산 칩에서는 보통 JTAG를 잠그거나(fuse) 인증을 겁니다.

물리 인터페이스

핀은 단 4개(+1) — TCK · TMS · TDI · TDO

JTAG는 동기식 직렬 인터페이스입니다. 데이터가 한 비트씩 시프트되어 들어가고 나옵니다 — SPI를 써봤다면 익숙한 모델입니다.

TCK
Test Clock — 모든 동작의 기준 클럭. 이 클럭에 맞춰 비트가 한 칸씩 이동.
TMS
Test Mode Select — TAP 상태머신을 움직이는 "방향키". 이 한 선의 0/1 패턴으로 상태를 옮김.
TDI
Test Data In — 칩 안으로 들어가는 직렬 데이터 입력.
TDO
Test Data Out — 칩 밖으로 나오는 직렬 데이터 출력.
TRST
(옵션) Test Reset — TAP 상태머신을 강제 리셋. 없어도 TMS로 리셋 가능.

멘탈 모델: TDI→칩→TDO는 하나의 긴 시프트 레지스터입니다. 비트를 밀어 넣으면(in) 반대편으로 비트가 밀려 나옵니다(out). 마치 bit-banging으로 직렬 프로토콜을 손수 돌리는 것과 같죠.

두뇌: 상태머신

TAP Controller — TMS로 움직이는 16-상태 FSM

TAP(Test Access Port) Controller는 JTAG의 두뇌인 유한 상태 기계입니다. 매 TCK마다 TMS 값(0/1) 하나만 보고 다음 상태로 이동합니다. "지금 명령어를 넣을 차례인지, 데이터를 넣을 차례인지"를 이 FSM이 결정합니다.

핵심만: FSM에는 두 갈래(IR 경로 / DR 경로)가 있고, TMS의 0/1 시퀀스로 원하는 경로로 들어갑니다. 각 경로는 실제로 Capture(값을 병렬로 적재)→Shift(비트 이동)→Update(확정) 순서로 동작하며, 다이어그램의 Shift 박스는 이 묶음을 줄인 것입니다. 16개 상태 이름을 외울 필요는 없습니다.
두 종류의 레지스터

IR과 DR — "명령"과 "데이터"의 분리

JTAG의 모든 동작은 두 단계입니다: 먼저 IR에 "무엇을 할지" 명령을 싣고, 그다음 DR로 실제 데이터를 주고받습니다. 마치 opcode를 먼저 정하고 그 opcode가 가리키는 레지스터를 조작하는 것과 같습니다.

📜 IR (Instruction Register)

  • "이번엔 어떤 동작?"을 고르는 명령어 레지스터
  • 예: BYPASS·SAMPLE/PRELOAD·EXTEST(필수), IDCODE(옵션) — IDCODE는 device ID 레지스터를 구현한 경우에만 제공
  • IR 값이 어느 DR이 연결될지를 결정

📦 DR (Data Register)

  • 실제 비트를 실어 나르는 데이터 레지스터
  • IR=IDCODE면 → 32비트 칩 ID가 흘러나옴
  • IR=EXTEST면 → boundary scan 셀들이 DR이 됨

개발자 비유: IR = 함수 선택, DR = 그 함수의 인자/리턴값 버퍼. 먼저 호출할 함수를 고르고(IR), 그다음 인자를 직렬로 밀어 넣고 결과를 직렬로 받아옵니다(DR). BYPASS는 그 칩을 1비트로 건너뛰는 "no-op"입니다.

JTAG의 원래 사명

Boundary Scan — 납땜·핀 연결을 칩이 스스로 검사

각 I/O 핀 옆에 boundary scan cell이라는 작은 래치를 심어, 그 셀들을 TDI→TDO로 줄줄이 엮어 하나의 긴 시프트 체인(scan chain)으로 만듭니다. 이 체인으로 핀 값을 강제로 쓰고(set) 읽어(capture) 보드 배선을 검사합니다.

동작: Chip A의 출력 셀에 1을 강제로 쓰고 → Chip B의 입력 셀에서 1이 읽히는지 확인. 안 읽히면 둘 사이 배선이 끊겼거나(냉납) 단락된 것. 오실로스코프 없이 보드 전체 연결을 검사하는 게 boundary scan의 핵심 가치입니다.
진화: 칩 안쪽으로

iJTAG (IEEE 1687) — 내부 계측기 수백 개에 효율적 접근

현대 칩 안에는 수많은 instrument(계측기)가 들어 있습니다 — 온도 센서, 메모리 BIST 엔진, 전압 모니터, eFuse 등. 이들을 전부 하나의 긴 scan chain에 박으면 접근이 너무 느립니다. iJTAG는 이 문제를 "재구성 가능한 네트워크"로 풉니다.

🔀 SIB의 마법

SIB(Segment Insertion Bit)는 체인 위의 "스위치"입니다. SIB를 열면 그 뒤 계측기가 체인에 끼어들고, 닫으면 통째로 건너뜁니다. 필요한 것만 체인에 넣어 길이를 동적으로 줄입니다.

⚡ 왜 빠른가

온도 센서 하나만 읽고 싶을 때, 1149.1이라면 칩의 전체 체인을 시프트해야 합니다. iJTAG는 그 센서가 매달린 SIB만 열어 짧은 체인만 돌리면 됩니다.

개발자 비유: 1149.1이 모든 항목을 한 줄로 엮은 고정 링크드 리스트라면, iJTAG는 필요한 노드만 동적으로 연결하는 라우팅 가능한 트리입니다. 한 줄 요약: iJTAG = JTAG TAP 위에 올린 "내부 계측기 접근 네트워크" 표준.

버스로 가는 다리

JTAG2APB — JTAG 접근을 APB 트랜잭션으로 변환

디버거는 JTAG라는 직렬 세계에 있고, 칩 내부 레지스터·주변장치는 APB 버스라는 병렬 세계에 있습니다. JTAG2APB는 그 사이의 브리지(번역기)입니다. (이는 IEEE 표준명이 아니라 업계에서 부르는 일반 기능 명칭이며, ARM에서는 CoreSight DAP의 APB-AP/AHB-AP가 같은 역할을 합니다.) JTAG로 들어온 "주소+데이터"를 진짜 APB 읽기/쓰기 트랜잭션으로 바꿔 줍니다.

🌉 무엇을 하나

JTAG의 IR/DR로 받은 주소·데이터·R/W를 풀어, PADDR/PWDATA/PWRITE 같은 APB 신호를 구동합니다. 응답(PRDATA)은 다시 DR에 실어 TDO로 내보냅니다.

🎯 왜 쓰나

  • 디버거가 칩 안 어떤 레지스터든 읽고 씀
  • 부팅 전·CPU 멈춘 상태에서도 버스 접근 가능
  • 전용 디버그 핀 없이 JTAG 4핀으로 끝

개발자 비유: 프로토콜 어댑터/게이트웨이입니다. 외부의 직렬 명령(JTAG)을 받아 내부 시스템 버스(APB) 호출로 변환하는 — HTTP 요청 → 내부 함수 호출 어댑터와 정확히 같은 패턴이죠. (APB는 AMBA 버스 중 가장 단순한 저속 주변장치 버스입니다.)

면접 예상 질문

이렇게 물어보면, 이렇게 답한다

JTAG가 뭔가요?
IEEE 1149.1 표준으로, 칩 외부에서 TCK·TMS·TDI·TDO 핀 몇 개만으로 내부에 접근하는 직렬 인터페이스입니다. 내부에 TAP controller라는 상태머신과 IR/DR 레지스터가 있어, 명령을 싣고 데이터를 시프트하는 방식으로 동작합니다. 원래 보드 검사용이었지만 지금은 디버깅·프로그래밍·테스트의 표준 통로로 쓰입니다.
Boundary scan이란 무엇인가요?
각 I/O 핀 옆에 scan cell을 두고 이들을 TDI→TDO로 하나의 체인으로 엮은 뒤, 핀 값을 강제로 쓰고 읽어 보드의 핀 연결·납땜을 검사하는 기법입니다. 한 칩 출력에 1을 쓰고 연결된 칩 입력에서 그 값이 읽히는지로 단선·단락을 잡아냅니다. 오실로스코프 없이 보드 배선을 검증할 수 있는 게 핵심입니다.
TAP controller가 뭐죠? iJTAG와 JTAG의 차이는요?
TAP controller는 TMS 입력으로 상태가 바뀌는 16-상태 유한 상태기계로, IR에 명령을 넣을지 DR로 데이터를 주고받을지를 제어합니다. iJTAG(IEEE 1687)는 1149.1의 TAP 위에 얹힌 표준으로, 내부 계측기들을 SIB라는 스위치로 재구성 가능한 네트워크로 묶어 필요한 것만 짧은 체인으로 접근합니다. JTAG는 보드 핀 검사 중심, iJTAG는 칩 내부 계측기 접근 중심입니다.
JTAG2APB는 왜 쓰나요?
디버거의 JTAG 접근을 내부 APB 버스 트랜잭션으로 변환하는 브리지입니다. 이걸 통하면 디버거가 JTAG 4핀만으로 칩 내부의 어떤 레지스터·주변장치든 직접 읽고 쓸 수 있습니다. CPU가 멈췄거나 부팅 전이어도 버스에 접근할 수 있어 디버깅·브링업에 유용합니다.
핵심 요약

이 챕터, 한 손에 잡기

  • JTAG(1149.1) = 핀 4개(TCK/TMS/TDI/TDO)로 칩에 접근하는 표준 뒷문
  • TAP controller = TMS로 움직이는 상태머신, IR=명령 / DR=데이터
  • Boundary scan = scan cell 체인으로 보드 핀 연결·납땜 검사
  • iJTAG(1687) = TAP 위에서 내부 계측기를 SIB로 재구성해 효율 접근
  • JTAG2APB = JTAG 접근을 APB 버스 트랜잭션으로 바꾸는 브리지
  • 용도 = 디버깅 · 프로그래밍 · 테스트 제어 (DFT의 표준 출입구)

"JTAG는 핀 4개로 칩 내부에 닿는 표준 뒷문이고, TAP·IR·DR로 동작합니다. boundary scan으로 보드 핀을 검사하고, iJTAG로 내부 계측기를, JTAG2APB로 내부 버스 레지스터까지 접근합니다."

— 4개 핀에서 시작해 셋의 관계로 마무리.
