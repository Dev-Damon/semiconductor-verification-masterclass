디지털 회로 복습
기억하지 못하는 회로 vs 기억하는 회로

AND·OR 게이트는 안다고 했죠. 그런데 칩은 어떻게 "이전 값을 기억"할까요? 이 한 장이면 조합·순차·클럭·플립플롭이 한 그림으로 연결됩니다.

← → 또는 Space 로 넘기기 · 화면 좌/우 끝 클릭도 가능
왜 이걸 먼저 보나

모든 칩은 단 두 종류의 회로로 이뤄져 있다

아무리 복잡한 SoC도 결국 조합논리(기억 없음)와 순차논리(기억 있음) 두 가지의 조합일 뿐입니다. 이 둘의 차이만 잡으면 RTL·검증 용어의 8할이 풀립니다.

🧮 조합논리 (Combinational)

입력이 들어오면 즉시 출력이 정해진다. 과거를 모른다. 출력은 오직 현재 입력만의 함수.

예: 가산기, 멀티플렉서, 비교기

📒 순차논리 (Sequential)

출력이 현재 입력 + 과거에 저장된 값으로 정해진다. 상태(state)를 기억한다. 클럭에 맞춰 갱신.

예: 카운터, 레지스터, FSM, CPU

한 문장: 조합 = 기억 없는 계산기, 순차 = 매 박자마다 기록하는 메모장. 칩은 이 둘을 번갈아 쌓아 만든 거대한 파이프라인입니다.
직관적으로 이해하기

일상 속에 이미 있는 두 개념입니다

조합논리 = 자판기 거스름돈 계산. 넣은 동전과 누른 버튼만 정해지면 거스름돈이 즉시 정해집니다. 과거에 무엇을 샀는지는 전혀 상관없습니다. 입력만으로 출력이 결정되는 것 — 그게 조합회로입니다.

순차논리 = 경기장 점수판. 다음 점수는 "지금 들어온 득점 + 지금까지 쌓인 점수"로 정해집니다. 그 "지금까지의 점수를 기억하는 칸"이 하드웨어에선 플립플롭/레지스터입니다.

일상의 예하드웨어 (반도체)
입력만으로 답이 나오는 계산기 (기억 없음)조합논리 (게이트 묶음)
지금까지의 값을 적어두는 점수판 한 칸플립플롭 / 레지스터
점수판에 새 숫자가 딱 바뀌는 그 순간클럭 엣지(posedge) — 값이 들어가는 순간
득점을 일제히 반영하는 호각 신호클럭(clock) — 전체 박자
핵심 ① 조합논리

게이트를 엮으면 "계산"이 된다 — 1비트 가산기

AND·OR·XOR 게이트만으로 덧셈기를 만들 수 있습니다. 입력 두 비트 A, B를 더하면 합(Sum)과 자리올림(Carry)이 나옵니다. 기억은 전혀 필요 없습니다 — 입력만 정해지면 출력이 즉시 결정됩니다.

진리표: A=1,B=1 → Sum=0, Carry=1 (즉, 1+1=10₂). 지금 이 회로는 자리올림 입력이 없는 반가산기(Half Adder)입니다. 여기에 캐리 입력(Cin)을 더한 전가산기(Full Adder)를 여러 개 이으면 32·64비트 덧셈기가 되죠 — ALU의 뼈대입니다.
핵심 ② 왜 기억이 필요한가

조합회로만으로는 "카운터"를 못 만든다

"버튼을 누른 횟수를 센다"를 생각해 보세요. 다음 값은 이전 값 + 1입니다. 그런데 조합회로는 과거를 모릅니다. 그래서 이전 값을 어딘가에 담아둘 그릇이 필요합니다.

  • 다음 상태 = f(현재 입력, 현재 상태)
  • "현재 상태"를 담는 그릇 = 플립플롭
  • 언제 갱신할지 정하는 신호 = 클럭

조합회로가 계산기라면, 순차회로는 메모장입니다. 계산기는 누를 때마다 답만 보여주고 잊지만, 메모장은 박자마다 한 줄씩 적어 두고 다음 계산에 씁니다.

그 "한 줄 적는 박자"가 바로 클럭입니다.

"세는 일"은 사실 두 단계로 나뉩니다: 먼저 조합논리가 (현재 값 + 1)을 계산하고, 그다음 플립플롭이 클럭 엣지에 그 결과를 저장합니다. 계산과 저장이 분리돼 있다는 점이 핵심입니다.
핵심 ③ 기억소자

D 플립플롭 = 1비트 기억소자, 레지스터 = 그 묶음

D 플립플롭(D-FF)은 RTL에서 가장 널리 쓰이는 기본 기억소자입니다. (1비트를 저장하는 가장 단순한 소자를 따지면 SR 래치가 더 밑단이고, D-FF은 그 래치를 클럭으로 제어해 만든 엣지 트리거 소자입니다.) 규칙은 단 하나:

"클럭이 올라가는 순간, 입력 D를 붙잡아 출력 Q로 내보내고, 다음 엣지까지 그 값을 유지한다."

  • D = 입력(저장할 값), Q = 출력(저장된 값)
  • 클럭 엣지 사이에는 입력이 흔들려도 Q는 안 바뀜
  • 레지스터 = D-FF를 N개 나란히 = N비트 기억 (예: 32비트 레지스터 = FF 32개)
// D 플립플롭: 클럭 상승 엣지마다 d를 q에 저장
always @(posedge clk) begin
  q <= d;        // "변수에 값이 대입되는 순간" = 클럭 엣지
end
핵심 ④ 클럭(clock)

클럭 = 칩 전체의 심장 박동 · 오케스트라 지휘자

클럭은 0과 1을 규칙적으로 반복하는 신호입니다. (같은 클럭을 쓰는) 모든 플립플롭은 거의 같은 박자에 함께 값을 갱신합니다. 그래서 수십억 개 소자가 어긋나지 않고 한 몸처럼 움직입니다. — 실제 칩에서는 클럭 도착 시각 차이(클럭 스큐) 때문에 완벽히 '동시'는 아니지만 같은 클럭 도메인 안에서는 한 몸처럼 움직이는 것으로 봐도 됩니다. (스큐/다중 클럭 도메인은 후속 챕터에서)

📈 edge-triggered

대부분의 회로는 클럭이 0→1로 올라가는 순간(posedge)에만 동작합니다. "레벨"이 아니라 "엣지" 그 한순간이 트리거입니다.

⏱️ 주파수

1초에 박자가 몇 번? 3GHz = 초당 30억 번. 주기가 짧을수록(빠를수록) 한 박자 안에 조합논리가 계산을 끝내야 하는 시간이 빠듯해집니다.

핵심 ⑤ 리셋과 타이밍 규칙

리셋 = 초기화, 그리고 "지킬 타이밍 규칙"이 있다

리셋(reset)은 플립플롭을 알려진 초기값(보통 0)으로 되돌리는 신호입니다. 전원이 켜진 직후 회로 상태는 쓰레기값이라, 리셋으로 출발점을 맞춰줍니다.

비유하자면 게임을 시작하기 전 점수판을 모두 0으로 맞춰 두는 일과 같습니다.

구분의미
Sync reset클럭 엣지에 맞춰 리셋 적용 (always 안에서 clk와 함께)
Async reset클럭과 무관하게 즉시 리셋 (엣지 안 기다림)

⚠️ setup / hold (맛보기)

플립플롭은 입력 D가 클럭 엣지 직전(setup)·직후(hold) 잠깐 동안은 흔들리지 않고 안정돼 있어야 값을 제대로 붙잡습니다.

이 규칙을 어기면 출력이 불안정(metastability)해집니다. "타이밍 규칙이 존재한다"는 사실만 지금은 기억하세요.

자세한 분석은 4-3 (타이밍/STA)에서 다룹니다.

// Async reset: rst가 뜨면 clk를 안 기다리고 즉시 0으로
always @(posedge clk or posedge rst)
  if (rst) q <= 0;     // 초기화
  else     q <= d;
핵심 ⑥ FSM 맛보기

순차회로의 꽃 — 유한상태기계(FSM)

FSM(Finite State Machine)은 "상태(state)" 사이를 입력에 따라 옮겨 다니는 회로입니다. 신호등, 프로토콜 핸드셰이크, 컨트롤러가 모두 FSM입니다. 핵심 부품은 딱 두 가지뿐입니다.

신호등을 떠올리면 쉽습니다. 빨강 → 초록 → 노랑 → 다시 빨강처럼 정해진 순서로 상태가 옮겨 다니죠. 하드웨어 FSM도 같은데, "다음 상태로의 전환"이 클럭 엣지마다 레지스터 갱신으로 일어난다는 점만 다릅니다. 정리하면 FSM = 조합논리(다음상태·출력 계산) + 순차논리(상태 저장)의 조합입니다.
면접 예상 질문

이렇게 물어보면, 이렇게 답한다

조합논리와 순차논리의 차이는?
조합논리는 출력이 오직 현재 입력만으로 결정되어 기억이 없습니다(예: 가산기). 순차논리는 현재 입력에 더해 저장된 상태(과거)에 의존하며, 플립플롭으로 상태를 기억하고 클럭에 맞춰 갱신합니다(예: 카운터, FSM). 한마디로 기억의 유무가 차이입니다.
클럭이 왜 필요한가요? 플립플롭은 뭔가요?
클럭은 모든 기억소자가 동시에 같은 박자로 값을 갱신하게 해주는 동기화 신호입니다. 이게 없으면 소자마다 갱신 시점이 달라 회로가 어긋납니다. 플립플롭은 1비트 기억소자로, 클럭 상승 엣지에 입력 D를 붙잡아 출력 Q로 유지합니다. 이 플립플롭을 여러 개 묶은 것이 레지스터입니다.
Sync reset과 Async reset의 차이는?
Sync reset은 클럭 엣지에 맞춰 리셋이 적용되고, Async reset은 클럭과 무관하게 신호가 들어오는 즉시 적용됩니다. Async는 전원 직후처럼 클럭이 안정되기 전에도 초기화할 수 있지만, 리셋 해제 시점이 클럭 엣지와 충돌하지 않도록 하는 처리가 필요합니다.
핵심 요약

이 챕터, 한 손에 잡기

  • 조합 = 입력만으로 출력 결정(기억X), 순차 = 저장된 상태에 의존(기억O)
  • 게이트(AND/OR/XOR)를 엮으면 가산기 같은 조합회로
  • D 플립플롭 = 1비트 기억, 레지스터 = FF 묶음
  • 클럭 = 전체 박자, posedge에 값 갱신(edge-triggered)
  • 리셋 = 초기화 (sync는 엣지에 맞춰, async는 즉시)
  • FSM = 조합(다음상태 계산) + 순차(상태 저장)

"조합논리는 입력만으로 출력이 정해지는 회로, 순차논리는 플립플롭에 상태를 저장하고 클럭 엣지마다 갱신하는 회로입니다."

— 이 한 문장이 RTL을 읽는 열쇠입니다.
