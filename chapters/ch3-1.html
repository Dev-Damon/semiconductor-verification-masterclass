왜 배우나 · 한 문장 정의

APB = 칩 안의 저속·저전력 표준 버스

APB(Advanced Peripheral Bus)는 ARM이 만든 AMBA 버스 패밀리의 멤버로, 빠른 데이터 전송이 필요 없는 제어·설정 레지스터 접근에 쓰는 가장 단순한 프로토콜입니다.

🐢 단순 / 저속

핸드셰이크가 적고 파이프라인이 없어 회로가 작고 이해하기 쉽습니다.

🔋 저전력 / 저대역

스위칭 신호가 적어 전력을 거의 안 먹습니다. 빠를 필요 없는 곳에 딱.

⚙️ 제어 레지스터용

UART·타이머·GPIO의 설정 레지스터를 읽고 쓰는 "관리 통로".

왜 면접에 나올까? AMBA는 거의 모든 SoC가 쓰는 사실상 표준입니다. APB는 그중 가장 단순해서 버스 프로토콜의 기본기를 묻기에 최적입니다.
AMBA 패밀리 위계

속도에 따라 도로를 나눠 쓴다

AMBA는 하나가 아니라 여러 프로토콜의 패밀리입니다. 빠른 데이터는 고속도로(AXI/AHB)로, 자잘한 설정은 골목길(APB)로 — 속도와 단순함을 맞바꾼 계층 구조입니다.

AXI
최고속 · 파이프라인 · 다중 채널
→
AHB
고속 · 버스트 전송
→
APB
저속 · 단순 ← 오늘
프로토콜속도/대역복잡도주 용도비유
AXI최고높음CPU↔메모리, 대용량 데이터고속도로(여러 차선·동시 통행)
AHB높음중간주 시스템 버스, 버스트국도(빠르지만 한 차선)
APB낮음낮음주변장치 제어 레지스터동네 골목길
실무에선 흔히 AXI/AHB로 들어온 요청을 브리지(bridge)가 APB로 변환해 느린 주변장치에 전달합니다. "고속도로에서 빠져 골목으로 들어가는 IC" 같은 역할입니다.
개발자 직관으로 번역

APB는 "동기 블로킹 REST 호출"이다

당신이 짠 이런 코드를 떠올려 보세요. 응답이 올 때까지 다음 줄로 못 넘어가고, 한 번에 요청 하나만 날아갑니다.

// APB의 멘탈 모델 = 이 코드
val resp = http.get("/reg/0x10")  // 읽기
http.post("/reg/0x14", 0xFF)    // 쓰기
// 둘은 절대 겹치지 않는다 (비파이프라인)

APB는 요청 → 응답이 또박또박 짝지어지는 동기 호출입니다. 서버가 느리면(준비가 안 되면) PREADY로 "잠깐만요" 하며 호출자를 블로킹시킵니다. 그래서 비동기·동시요청을 다루는 AXI보다 훨씬 단순합니다.

또는 우체국 창구를 떠올리세요. 우편물 한 통을 직원에게 건네고(주소+내용), 직원이 처리 끝났다고 도장 찍어줄 때까지 기다립니다. 다음 사람은 그 다음. 줄 서서 한 번에 한 통씩 — 이게 APB입니다.

핵심 신호 (Signals)

APB가 주고받는 9개의 선

버스는 결국 전선 묶음 + 약속입니다. APB는 신호가 적어서 외우기 쉽습니다. Master(요청자, 보통 브리지) ↔ Slave(주변장치) 사이 신호를 봅시다.

PCLK
버스 클럭. 모든 동작의 박자.
PSEL
"너 호출이야" — 이 슬레이브 선택 신호.
PENABLE
ACCESS 페이즈 진입 표시(2번째 클럭).
PADDR
접근할 주소 (어느 레지스터?).
PWRITE
1=쓰기, 0=읽기.
PWDATA
쓸 데이터 (Master→Slave).
PRDATA
읽은 데이터 (Slave→Master).
PREADY
슬레이브 "준비됨/끝났음" 신호.
PSLVERR
에러 응답 (1이면 실패).

개발자 매핑: PADDR=URL 경로, PWRITE=GET/POST 구분, PWDATA=요청 바디, PRDATA=응답 바디, PREADY=200 응답 도착(블로킹 해제), PSLVERR=HTTP 500/4xx. P는 전부 Peripheral의 P입니다.

트랜잭션 상태 머신

모든 거래는 IDLE → SETUP → ACCESS

APB 한 번의 읽기/쓰기는 항상 이 상태 흐름을 탑니다. 핵심은 SETUP과 ACCESS, 단 2개의 활성 페이즈로 끝난다는 것.

다음 거래

① SETUP (항상 1클럭)

PSEL=1로 슬레이브를 깨우고 PADDR/PWRITE/PWDATA를 선 위에 올립니다. 아직 PENABLE=0. "요청서 작성 단계".

② ACCESS (1클럭 이상)

PENABLE=1. 실제 데이터 전송이 일어나고 PREADY=1이 될 때까지 머뭅니다. "제출하고 처리 기다리는 단계".

타이밍 다이어그램

파형으로 보는 APB 쓰기 1회

아래는 PREADY가 한 번 0으로 떨어져 대기 사이클(wait state)이 1번 들어간 쓰기 트랜잭션입니다. 페이즈를 색으로 표시했습니다.

읽어내는 법: SETUP 1클럭 동안 주소/데이터를 세팅 → ACCESS에서 PENABLE이 뜨고, 슬레이브가 느리면 PREADY=0으로 호출자를 잡아둡니다. PREADY=1이 뜬 클럭에 전송이 완료됩니다.
비파이프라인 (Non-pipelined)

"한 번에 하나" — 겹치지 않는다

APB의 가장 큰 특징이자 한계입니다. 한 트랜잭션이 완전히 끝나야 다음이 시작됩니다. 거래가 절대 겹치지 않으니 회로는 단순하지만, 대역폭은 낮습니다.

관점APB (비파이프라인)AXI (파이프라인/다중 채널)
동시 진행 거래항상 1개여러 개 (outstanding) 동시 진행
주소/데이터 채널공유, 직렬읽기/쓰기 주소·데이터 채널 분리
버스트 전송없음 (한 번에 1워드)있음 (한 요청에 여러 워드)
순서 바꾸기불가 (순차)가능 (out-of-order, ID로 구분)
개발자 비유동기 블로킹 호출async/await + 동시 요청 풀

AXI가 비동기 + 커넥션 풀이라면, APB는 한 줄짜리 동기 호출 루프입니다. 그래서 주변장치 설정처럼 가끔, 조금만 오가면 되는 곳엔 APB가 정답입니다 — 굳이 비싼 비동기 인프라를 깔 이유가 없죠.

면접 예상 질문

이렇게 물어보면, 이렇게 답한다

APB는 언제 쓰나요? AXI와 비교하면?
고대역이 필요 없는 주변장치의 제어·설정 레지스터 접근에 씁니다. UART·타이머·GPIO 설정값을 읽고 쓰는 용도죠. AXI는 다중 채널·파이프라인·버스트로 고속 대용량 전송(CPU↔메모리)에 쓰지만 복잡합니다. 보통 AXI/AHB 요청을 브리지가 APB로 변환해 느린 주변장치에 전달합니다. 단순/저전력이 필요하면 APB, 속도가 필요하면 AXI입니다.
SETUP과 ACCESS 페이즈의 차이는?
SETUP은 항상 1클럭으로, PSEL=1·PENABLE=0 상태에서 PADDR/PWRITE/PWDATA를 버스에 올려 슬레이브를 준비시킵니다. 다음 클럭의 ACCESS에서 PENABLE=1이 되어 실제 전송이 일어나고, PREADY=1이 될 때까지 ACCESS에 머뭅니다. 즉 SETUP은 "요청서 작성", ACCESS는 "제출하고 완료를 기다리는" 단계입니다.
PREADY와 PSLVERR의 역할은?
PREADY는 슬레이브의 핸드셰이크 신호로, 0이면 아직 준비 안 됨(대기 사이클을 삽입해 마스터를 블로킹), 1이면 이번 클럭에 전송 완료를 뜻합니다. 느린 주변장치가 속도를 맞추는 수단이죠. PSLVERR은 에러 응답으로, ACCESS의 마지막 클럭에 1이면 그 트랜잭션이 실패(잘못된 주소·쓰기 금지 영역 등)했음을 알립니다. HTTP로 치면 PREADY는 응답 도착, PSLVERR은 500 에러에 해당합니다.
핵심 요약

이 챕터, 한 손에 잡기

  • APB = AMBA 패밀리 중 가장 단순·저속·저전력 버스, 제어 레지스터용
  • 위계: AXI(최고속) ↔ AHB ↔ APB(저속). 보통 브리지로 연결
  • 신호: PCLK/PSEL/PENABLE/PADDR/PWRITE/PWDATA/PRDATA/PREADY/PSLVERR
  • 상태: IDLE → SETUP → ACCESS (2 활성 페이즈)
  • 비파이프라인: 한 번에 하나, 거래가 겹치지 않음

"APB는 AMBA에서 가장 단순한 동기·비파이프라인 버스로, SETUP/ACCESS 2페이즈로 주변장치 제어 레지스터를 한 번에 하나씩 읽고 씁니다."

— 마치 동기 블로킹 REST 호출처럼.
