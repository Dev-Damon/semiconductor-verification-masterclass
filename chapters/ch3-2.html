AMBA AXI
칩 안의 다차선 고속도로

읽기와 쓰기가 따로 달리고, 수십 개의 요청이 동시에 처리 중인 채로 흐르며, 송장번호(ID)로 순서가 뒤섞여도 다 추적되는 버스. 다차선 고속도로를 떠올리면 절반은 이해한 셈입니다.

한 문장 정의

AXI = 고성능 블록들을 잇는 고속 버스 약속

AXI(Advanced eXtensible Interface)는 ARM AMBA 제품군의 고성능 온칩 버스 프로토콜입니다. CPU·GPU·DRAM 컨트롤러처럼 대역폭이 중요한 블록들을 연결합니다.

🛣️ AXI가 노리는 것

  • 높은 처리량: 읽기/쓰기 동시, 여러 요청 동시
  • 주소와 데이터를 분리해 파이프라이닝
  • 긴 데이터 묶음(버스트)을 한 번에 전송

🧭 왜 면접에 나오나

  • SoC 안 거의 모든 IP가 AXI로 대화 → 검증 단골
  • VIP(Verification IP)·UVM 환경의 핵심 대상
  • 핸드셰이크·outstanding·burst는 단골 질문
AMBA 제품군: 저속·단순 제어용 APB, 중간 성능의 AHB(Advanced High-performance Bus), 그리고 최고 성능의 AXI. (캐시 일관성이 필요한 멀티코어에는 더 상위인 ACE·CHI가 쓰입니다.) 이번 챕터는 AXI에 집중합니다.
직관적으로 이해하기

AXI는 "송장번호로 추적되는 다차선 물류망"이다

새로운 마법이 아니라, 우리가 아는 고속도로와 택배 시스템의 발상이 전선 위에 구현된 것입니다.

신호등 있는 진입로: 각 채널은 보내는 쪽이 "보낼 게 준비됐다"(VALID)고 손을 들고, 받는 쪽이 "받을 준비됐다"(READY)고 손을 들어야만 차 한 대가 지나갑니다. 한쪽이라도 손을 안 들면 차가 멈춰 서서 기다립니다 — 마치 양쪽이 동시에 OK해야 통과시키는 톨게이트와 같습니다.

다차선 고속도로: 읽기 차선과 쓰기 차선이 따로 있어 서로 막지 않고, 여러 차(트랜잭션)가 동시에 달립니다. 각 차에는 택배 송장번호(ID)가 붙어 있어, 도착 순서가 뒤섞여도 어느 요청의 응답인지 추적됩니다.

AXI 개념일상 비유
VALID / READY 핸드셰이크양쪽이 동시에 OK해야 차 한 대를 통과시키는 톨게이트
Outstanding 트랜잭션답을 기다리지 않고 주문서 여러 장을 연달아 접수 (동시에 처리 중)
ID 기반 out-of-order택배마다 붙은 송장번호로 도착 순서가 뒤섞여도 추적
Burst주문서 한 장으로 여러 개 묶음 배송 (대량 한 번에)
핵심 구조 · 5개 독립 채널

읽기 3채널 + 쓰기 2채널, 모두 따로 움직인다

AXI의 정체성은 5개의 독립 채널입니다. 각 채널은 자기만의 VALID/READY를 갖고 독립적으로 흐릅니다. 핵심: 주소 채널과 데이터 채널이 분리되어 있다는 점.

화살표 방향에 주목: AW·W·AR는 Master→Slave, B·R는 Slave→Master로 되돌아옵니다. 모든 채널은 서로를 기다리지 않고 독립적으로 진행합니다.
5채널 한눈에

각 채널의 역할과 방향

채널이름방향나르는 것
AWWrite AddressM → S쓸 주소 + 버스트 정보(len/size/burst)
WWrite DataM → S실제 쓸 데이터(여러 비트 + byte strobe)
BWrite ResponseS → M쓰기 완료 응답 (OKAY/SLVERR 등)
ARRead AddressM → S읽을 주소 + 버스트 정보
RRead DataS → M읽은 데이터 + 응답 (버스트로 여러 번)

쓰기는 3박자: "여기에 써줘(AW)" + "이게 데이터(W)" → "다 썼어(B)". 읽기는 2박자: "여기 좀 읽어줘(AR)" → "여기 있어(R)".

쓰기 응답 채널 B가 따로 있는 이유: 택배를 보내기만 하고 끝나는 게 아니라, "정말 잘 받았다"는 수령 확인서가 돌아와야 완료로 칩니다. 보낸 쪽은 이 확인을 받기 전까지는 안심할 수 없습니다.

핵심 메커니즘 · 핸드셰이크

VALID/READY — 양쪽이 준비돼야 한 칸 전송

모든 5채널이 똑같은 규칙을 씁니다. 송신자가 VALID=1, 수신자가 READY=1 인 클럭 에지에서만 데이터가 전송됩니다. 둘 중 하나라도 0이면 멈춰서 기다립니다 = 백프레셔.

중요 규칙: 송신자는 VALID를 한 번 띄우면 전송이 성립할 때까지 내려선 안 됩니다(데이터도 유지). 반대로 READY는 VALID와 무관하게 올렸다 내려도 됩니다.

"VALID/READY는 양쪽 합의로만 1칸 전진하는 배압 핸드셰이크다." — 이 한 줄이면 면접관이 끄덕입니다.

처리량의 비결 (1)

주소·데이터 분리 + 다중 Outstanding

주소/데이터 분리

주소를 보내는 채널(AW/AR)과 데이터 채널(W/R)이 분리돼 있어, 한 트랜잭션의 데이터가 흐르는 동안 다음 트랜잭션의 주소를 미리 발사할 수 있습니다. → 파이프라이닝.

Outstanding

응답(B/R)을 받기 전에 여러 요청을 연달아 발사해 둘 수 있습니다. 동시에 "처리 대기 중"인 트랜잭션 수 = outstanding. 메모리 지연을 숨겨 대역폭을 채웁니다.

커피 주문 줄을 떠올리세요. 한 손님의 음료가 다 나올 때까지 다음 주문을 안 받으면(한 건씩 끝까지 대기) 줄이 멈춰 섭니다. AXI는 응답을 기다리지 않고 주문을 연달아 접수해 두는 방식이라, 주방(메모리)이 음료를 만드는 동안에도 새 주문이 계속 들어가 처리 능력을 꽉 채웁니다.

즉 "A 읽기 → 결과 대기 → B 읽기"처럼 한 건씩 기다리는 대신, "A·B·C 읽기 요청을 먼저 다 던져두고" 결과가 준비되는 대로 받아옵니다.

처리량의 비결 (2)

ID로 순서를 뒤섞는다 — Out-of-Order 완료

모든 트랜잭션에는 ID(AWID/ARID 등)가 붙습니다. 덕분에 응답이 보낸 순서와 다르게 돌아와도 어느 요청의 응답인지 매칭됩니다. 느린 메모리 뱅크를 기다리느라 빠른 응답이 막히는 일을 없앱니다.

단, 같은 ID를 가진 트랜잭션끼리는 순서가 보장됩니다(in-order). 서로 다른 ID 사이에서만 재정렬이 허용됩니다. 그래서 순서가 중요하면 같은 ID로, 성능이 중요하면 ID를 다르게 씁니다.
대역폭의 비결 · Burst

버스트 — 한 번의 주소로 여러 박자 전송

주소를 매번 보내지 않고, "이 주소부터 N개 연속 전송"을 한 번에 약속합니다. 주소 오버헤드를 없애 대역폭을 끌어올립니다. 주소 채널의 제어 신호가 버스트를 정의합니다.

📏 LEN

버스트 안 전송 개수(beats). 인코딩은 AxLEN = beats−1 → 예: AxLEN=3 이면 4 beats. (AXI3: AxLEN 4비트 → 모든 버스트 최대 16 beats. AXI4: AxLEN 8비트 → INCR만 최대 256 beats, FIXED·WRAP은 여전히 최대 16 beats.)

📦 SIZE

한 박자(beat)당 바이트 수. 인코딩은 2^AxSIZE 바이트 → 예: AxSIZE=2 이면 4바이트.

🔀 BURST 타입

INCR: 주소 증가. WRAP: 경계서 되감김(캐시 라인 충전용, 버스트 길이는 2·4·8·16 beats만 허용). (FIXED도 있음 — 같은 주소 반복)

트레이드오프 · AXI vs APB

왜 다 AXI로 안 쓰고 APB도 쓸까?

관점APB (저속·단순)AXI (고성능)
채널 구조단일, 공유 (주소+데이터 묶임)5개 독립 채널
파이프라인 / 동시성없음 (한 번에 1트랜잭션)주소·데이터 분리, outstanding
버스트없음INCR / WRAP 지원
순서 재정렬해당 없음ID 기반 out-of-order
처리량낮음높음
면적·복잡도(게이트)작고 단순크고 복잡
쓰는 곳레지스터 설정·저속 주변장치(UART 등)CPU·DRAM·GPU 등 데이터 고속도로

트레이드오프 한 줄: AXI는 성능을 위해 복잡도·게이트 면적·검증 부담을 지불합니다. 빠를 필요 없는 제어 레지스터까지 AXI로 깔면 칩 면적과 검증 비용만 낭비됩니다. 그래서 고속은 AXI, 저속 설정은 APB로 역할을 나눕니다.

면접 예상 질문

이렇게 물어보면, 이렇게 답한다

AXI의 5개 채널을 말해보세요.
쓰기 3개 — AW(쓰기 주소), W(쓰기 데이터), B(쓰기 응답), 읽기 2개 — AR(읽기 주소), R(읽기 데이터)입니다. 다섯 채널은 각자 VALID/READY를 갖고 독립적으로 동작하며, 특히 주소 채널과 데이터 채널이 분리돼 있어 파이프라이닝이 가능합니다.
VALID/READY 핸드셰이크 원리는?
송신자가 VALID=1, 수신자가 READY=1인 클럭 에지에서만 한 beat가 전송됩니다. 둘 중 하나라도 0이면 멈춰 기다리는 백프레셔 구조입니다. 또 VALID는 한 번 띄우면 전송 성립 전까지 내릴 수 없고 데이터도 유지해야 한다는 규칙이 있습니다.
Outstanding과 out-of-order는 무엇이고 왜 필요한가요?
Outstanding은 응답을 기다리지 않고 여러 트랜잭션을 미리 발사해 동시에 처리 중인 상태로 두는 것으로, 메모리 지연을 숨겨 대역폭을 채웁니다. Out-of-order는 각 트랜잭션의 ID 덕분에 응답이 보낸 순서와 달리 도착해도 매칭되는 것입니다. 단 같은 ID끼리는 순서가 보장됩니다.
APB 대신 AXI를 쓰는 장점과 트레이드오프는?
장점은 5채널 분리·outstanding·버스트로 처리량이 훨씬 높다는 것입니다. 트레이드오프는 게이트 면적·복잡도·검증 부담이 크다는 점이라, 빠를 필요 없는 제어 레지스터나 저속 주변장치는 단순한 APB로 처리하는 게 효율적입니다.
핵심 요약

이 챕터, 한 손에 잡기

  • AXI = AMBA의 고성능 버스, 5개 독립 채널 (AW·W·B / AR·R)
  • 모든 채널이 VALID/READY 핸드셰이크 → 배압(백프레셔)
  • 주소·데이터 분리 + outstanding = 여러 요청을 동시에 처리해 대역폭 확보
  • ID 기반 out-of-order 완료 (같은 ID는 in-order)
  • 버스트(INCR/WRAP, len/size)로 주소 오버헤드 절감
  • vs APB: 빠르지만 복잡·큼 → 역할 분담

"AXI는 읽기/쓰기 5채널을 VALID/READY 배압으로 굴리고, ID로 여러 요청을 동시에·순서 뒤섞어 처리하는 고성능 온칩 버스입니다."

— 다차선 고속도로 + 택배 송장번호. 이 두 비유면 충분합니다.
