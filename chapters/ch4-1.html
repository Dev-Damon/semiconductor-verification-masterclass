HDL 시뮬레이터의 빌드 3단계

당신이 매일 하는 compile → link → run. 시뮬레이터도 똑같이 3박자로 돕니다. 이 한 장으로 "elaboration이 정확히 뭐냐"는 면접 단골 질문을 끝냅니다.

왜 배우나 · 한 문장 정의

"시뮬레이션 돌려봐"는 사실 3단계다

HDL 시뮬레이션은 Compile → Elaboration → Simulation 세 단계를 거쳐야 비로소 파형이 나옵니다. 한 단계로 뭉뚱그려 알면 에러 로그를 못 읽습니다.

🥬 Compile

재료 손질. 소스 파일을 하나씩 문법 검사하고 중간 형식으로 변환. 모듈/파일 단위

🍳 Elaboration

레시피대로 조립·세팅. 계층을 펼쳐 연결하고 파라미터를 확정해 실행 가능한 모델을 빌드. 설계 전체 단위

🔥 Simulation

실제 조리. 시뮬레이션 시간이 흐르며 이벤트가 발생하고 파형이 그려짐. 시간 진행

이 3단계는 표준(IEEE 1800/1364)에 정의된 정식 흐름이며, VCS·Questa·Xcelium 등 모든 상용 시뮬레이터가 따릅니다.
개발자 직관으로 번역

이건 그냥 SW 빌드와 1:1이다

단계소프트웨어 (당신의 세계)HDL 시뮬레이션
1단계각 .c → .o (파일별 컴파일)Compile · 모듈별 문법검사 → 중간형식
2단계링킹 + 인스턴스화/초기화 (심볼 연결, 객체 배치)Elaboration · 계층 연결·파라미터 확정·메모리 할당
3단계프로그램 실행 ./a.outSimulation · 시간 진행하며 이벤트 실행

핵심 멘탈 모델: Compile = 컴파일러, Elaboration = 링커(+초기화), Simulation = 런타임. 그래서 에러도 SW처럼 "컴파일 에러 / 링크 에러 / 런타임 에러"로 나뉩니다. 이 대응만 외우면 면접의 절반은 끝납니다.

전체 흐름 한눈에

소스에서 파형까지, 3단계의 여정

왼쪽 → 오른쪽으로 갈수록 "더 구체적"이 됩니다. 컴파일은 파일을 따로따로 보고, elaboration에서 비로소 전체가 하나로 연결되며, 시뮬레이션에서 그 모델이 시간 위를 달립니다.
① Compile (= Analyze)

재료 손질: 파일을 하나씩 검사한다

HDL 소스를 읽어 문법(syntax)과 의미(semantic)를 검사하고, 시뮬레이터가 쓸 중간 형식으로 변환해 라이브러리에 저장합니다.

  • 단위 = 모듈/파일. 다른 파일과 연결은 아직 안 함
  • 타입 오류, 세미콜론 누락, 미선언 변수 등을 여기서 잡음
  • VHDL 진영에선 이 단계를 Analyze라고 부름 (같은 것)
  • SW의 gcc -c file.c → file.o 와 동일한 자리

요리로 치면 재료 손질입니다. 양파 까고, 고기 자르고 — 각 재료를 따로 다듬을 뿐, 아직 냄비에 같이 넣지 않습니다. "이 양파 상했네"(문법 오류)는 이 단계에서 걸러집니다.

옆 재료(다른 모듈)가 뭔지는 아직 신경 쓰지 않습니다.

compile vs elaboration: 컴파일은 "이 모듈 하나가 말이 되나"만 봅니다. 모듈 A가 모듈 B를 인스턴스화하더라도, B가 진짜 존재하는지는 여기서 따지지 않습니다 — 그건 다음 단계의 일.
② Elaboration · 가장 자주 묻는 단계

레시피대로 조립: 설계를 "하나로 완성"한다

컴파일된 조각들을 실제로 연결해 실행 가능한 단일 모델(이미지)을 만드는 단계. 면접에서 가장 깊게 파고드는 곳입니다.

🧩 elaboration이 하는 일

  • 계층 펼치기: top → 하위 모듈을 모두 인스턴스화해 설계 트리 구축
  • 연결(binding): 포트끼리, 신호끼리 실제로 와이어 연결
  • 파라미터 확정: parameter/generate 값을 계산해 고정
  • 메모리 할당: 모든 신호·레지스터·메모리 공간 확보

SW의 "링킹 + 인스턴스화/초기화" 그 자체입니다. .o들을 묶어 심볼을 풀고(링킹), 전역 객체를 생성·초기화하는 단계와 일대일로 대응됩니다.

결과물 = "실행 이미지". 아직 1ns도 흐르지 않았지만, 이제 돌릴 준비가 끝난 상태.

면접 정답 한 줄: "Elaboration은 컴파일된 모듈들을 계층적으로 인스턴스화하고, 포트를 연결하고, 파라미터를 확정하고, 메모리를 할당해 실행 가능한 시뮬레이션 모델을 빌드하는 단계입니다."
elaboration-time의 정체

"왜 파라미터는 컴파일이 아니라 elaboration?"

모듈 하나만 보면 파라미터 값을 모릅니다. 인스턴스화될 때 비로소 어떤 값이 꽂히는지 정해지죠. 그래서 파라미터 확정·generate 펼치기는 elaboration-time에 일어납니다.

  • parameter WIDTH = 8; → 인스턴스마다 다른 값 가능
  • generate for-loop → elaboration에서 하드웨어로 펼쳐짐
  • 이때 정해진 구조는 시뮬레이션 내내 고정 (런타임에 안 바뀜)
// 모듈 정의: WIDTH는 아직 미정
module fifo #(parameter WIDTH=8)(...);
endmodule

// elaboration-time에 값이 확정됨
fifo #(.WIDTH(16)) u_big (...);
fifo #(.WIDTH(4))  u_small (...);

// generate: 구조 자체가 펼쳐진다
genvar i;
generate for (i=0;i<4;i++) begin
  adder u_add (...);   // 4개 인스턴스 생성
end endgenerate
핵심: 하드웨어의 "구조"는 elaboration에서 못 박힙니다. SW처럼 런타임에 객체를 동적으로 새로 만드는 일이 RTL엔 없습니다 — 회로는 실물이니까요.
③ Simulation

실제 조리: 시간을 흘려 이벤트를 처리한다

완성된 모델을 이벤트 기반(event-driven)으로 실행합니다. 신호가 바뀌면(이벤트) 그 영향을 받는 회로만 다시 평가하며, 시뮬레이션 시간을 0부터 앞으로 진행합니다.

  • 이벤트 큐: "시각 t에 신호 X 변함" 이벤트를 시간순 처리
  • 매 시각마다 영향받는 블록만 재평가 → 효율적
  • 결과를 파형(VCD/FSDB)으로 덤프 → 파형 뷰어로 디버그
  • SW의 "프로그램 실행(runtime)"에 해당

불 켜고 실제로 조리하는 단계. 재료(신호)들이 시간에 따라 익어가고(값이 바뀌고), 그 과정을 영상(파형)으로 녹화합니다.

중요한 차이: 벽시계 시간이 아니라 시뮬레이션 시간(가상 시간)이 흐릅니다. 무거운 칩은 1µs 시뮬레이션에 실제 몇 분이 걸리기도 합니다.

에러는 어느 단계에서 터지나

compile-time vs elaboration-time vs run-time

종류언제대표 예시SW 대응
compile-time ① 모듈 문법/타입 검사 세미콜론 누락, 미선언 신호, 타입 불일치, 키워드 오타 컴파일 에러
elaboration-time ② 연결·파라미터·인스턴스화 없는 모듈 인스턴스화, 포트 폭 불일치/미연결, 파라미터로 음수 크기, 중복 인스턴스명 링크 에러
run-time ③ 시간 진행 중 실행 배열 인덱스 범위 초과, 0으로 나눔, $fatal/assertion 실패, X 전파 런타임 에러(세그폴트 등)

면접 함정: "없는 모듈을 인스턴스화하면?" → elaboration-time 에러입니다(컴파일 X). 모듈 하나만 볼 땐 문법이 멀쩡하고, 연결하려는 순간 비로소 "그런 모듈 없다"가 드러나니까요. SW에서 함수 선언만 있고 정의가 없을 때 링크 단계에서 undefined reference가 뜨는 것과 똑같습니다.

이렇게 물어보면, 이렇게 답한다

시뮬레이션 3단계를 각각 설명해보세요.
Compile은 HDL 소스를 모듈 단위로 문법·의미 검사해 중간 형식으로 변환합니다. Elaboration은 그 모듈들을 계층적으로 인스턴스화·연결하고 파라미터를 확정해 실행 가능한 모델을 빌드합니다. Simulation은 그 모델을 이벤트 기반으로 시간을 진행시키며 실행하고 파형을 생성합니다. SW의 compile → link → run과 1:1로 대응됩니다.
Elaboration이 정확히 뭔가요?
컴파일된 모듈들을 top부터 계층적으로 인스턴스화해 설계 트리를 만들고, 포트·신호를 실제로 연결(binding)하고, parameter와 generate를 펼쳐 확정하고, 모든 신호·메모리를 할당해 실행 가능한 시뮬레이션 이미지를 만드는 단계입니다. SW의 링킹+초기화에 해당하며, 이 단계가 끝나면 설계 구조가 고정됩니다.
compile-time과 elaboration-time, run-time 에러를 예로 구분해 주세요.
세미콜론 누락이나 미선언 변수는 compile-time입니다. 존재하지 않는 모듈을 인스턴스화하거나 포트 폭이 안 맞는 건 연결할 때 드러나므로 elaboration-time입니다. 배열 인덱스 초과나 assertion 실패처럼 시간이 흐르며 특정 값에서 터지는 건 run-time입니다.
핵심 요약

이 챕터, 한 손에 잡기

  • Compile = 재료 손질 · 모듈별 문법검사 → 중간형식 · SW: .c→.o
  • Elaboration = 조립 · 인스턴스화·연결·파라미터확정·메모리할당 → 실행 모델 · SW: 링킹+초기화
  • Simulation = 조리 · 이벤트 기반 시간진행 → 파형 · SW: 실행
  • 에러도 3종: compile / elaboration(=링크) / run-time
  • 없는 모듈·포트 폭 불일치 = elaboration 에러 (단골 함정)

"HDL 시뮬레이션은 compile→elaboration→simulation 3단계로, SW의 compile→link→run과 1:1 대응됩니다. 특히 elaboration은 모듈을 인스턴스화·연결하고 파라미터를 확정해 실행 모델을 빌드하는 링크 단계입니다."
