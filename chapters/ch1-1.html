왜 배우나 · 한 문장 정의

Verilog = 하드웨어를 적는 프로그래밍처럼 생긴 언어

Verilog는 HDL(Hardware Description Language) 입니다. 회로도를 그림으로 그리는 대신, 텍스트로 회로를 기술(description)하는 언어죠.

❓ 왜 글로 적나

요즘 칩엔 트랜지스터가 수백억 개. 손으로 회로도를 그릴 수 없습니다. 그래서 코드로 기술 → 도구가 자동으로 회로로 변환(합성)합니다.

🔬 검증 엔지니어가 왜 알아야

설계자가 쓴 Verilog(=검증 대상, DUT)를 읽고 이해해야 테스트를 짭니다. 또 테스트벤치 자체도 Verilog 계열로 작성합니다.

DUT = Design Under Test, 즉 당신이 검증할 대상 회로. 실무에선 SystemVerilog를 쓰지만, 그 뿌리이자 핵심 문법이 바로 Verilog입니다.

가장 중요한 차이: 일반 코드는 위에서 아래로 한 줄씩 실행되지만, Verilog의 assign·always 블록들은 전부 동시에(병렬로) 항상 살아 있습니다. 순서가 아니라 "관계"를 적는다고 생각하세요. 엑셀에서 셀 100개에 수식을 걸어두면 한 칸만 바꿔도 관련된 셀이 동시에 다시 계산되는 것과 같습니다.

기본 단위 · module

module = 함수, port = 입출력 인자

모든 Verilog 설계는 module 단위로 만듭니다. 입력(input)과 출력(output) 포트를 선언하고, 그 안에서 입력으로 출력을 어떻게 만들지 기술합니다.

  • module = 함수/클래스 정의
  • input = 들어오는 인자
  • output = 돌려주는 값(출력 핀)
  • [3:0] = 4비트 묶음(버스), 배열 폭처럼 생각
// 2비트를 더해 합을 내보내는 회로
module adder (
  input  [1:0] a,   // 입력 2비트
  input  [1:0] b,
  output [2:0] sum  // 출력 3비트
);
  assign sum = a + b;
endmodule
포트 폭 [2:0]은 비트 3개(2,1,0)를 뜻합니다. SW의 uint8_t처럼 "이 신호는 몇 비트짜리냐"를 정하는 것.
핵심 개념 · 데이터 타입

wire vs reg — 가장 많이 헷갈리는 둘

관점wirereg
비유전선(연결선)변수(값을 담는 그릇)
값을 주는 법assign 으로만always 블록 안에서만
값 유지스스로 못 함, 항상 입력에 끌려감새 값 줄 때까지 유지
주 용도조합 회로 연결always 블록 출력 (조합·순차 둘 다)

흔한 오해: reg 라는 이름 때문에 "무조건 레지스터(기억소자)"라고 생각하기 쉽지만, 아닙니다. reg는 단지 "always 블록에서 값을 대입받는 변수 종류"일 뿐입니다. 실제로 플립플롭이 되느냐는 @(posedge clk)를 쓰느냐로 결정됩니다.

규칙만 외우면 됩니다: assign으로 주는 신호 = wire, always에서 주는 신호 = reg. (SystemVerilog에선 logic 하나로 통합되지만 개념은 같습니다.)
조합 회로 · assign

assign = 연속 할당 = 조합 논리

assign은 "이 등호 관계를 항상 유지하라"는 뜻입니다. 오른쪽이 바뀌면 왼쪽이 즉시 따라 바뀝니다 — 기억 없이 입력만으로 출력이 정해지는 조합 회로.

예시는 2:1 MUX(멀티플렉서): 선택 신호 sel에 따라 두 입력 중 하나를 고르는 회로. SW의 삼항 연산자 sel ? a : b 그 자체입니다.

스프레드시트에서 =IF(sel, a, b)를 셀에 걸어둔 것과 똑같습니다. a나 sel을 바꾸는 순간 결과 셀이 자동 갱신되죠.

// 2:1 MUX — 입력 둘 중 하나 선택
module mux2 (
  input  a, b, sel,
  output y
);
  // sel=1 이면 a, 아니면 b
  assign y = sel ? a : b;
endmodule
always 블록 · 두 얼굴

@(*)는 조합, @(posedge clk)는 순차

같은 always 블록이지만 감도 리스트(@뒤의 조건)에 따라 전혀 다른 회로가 됩니다. 이 차이가 Verilog의 핵심입니다.

⚡ always @(*) — 조합

"입력 아무거나 바뀌면 즉시 다시 계산". 기억 없음. assign을 if/case로 풀어 쓴 버전이라 보면 됩니다.

always @(*) begin
  if (sel) y = a;
  else    y = b;
end

⏰ always @(posedge clk) — 순차

"클럭이 0→1로 올라가는 순간에만 실행". 즉 매 클럭 호출되는 콜백. 값을 다음 클럭까지 기억 → 플립플롭(레지스터)이 됩니다.

always @(posedge clk) begin
  q <= d;   // 매 클럭, d를 q에 저장
end

posedge = positive edge(상승 엣지). setInterval로 거는 콜백이 아니라, 클럭이라는 공용 심장박동에 모든 순차 회로가 동시에 깨어나 한 박자 전진한다고 생각하세요.

순차 회로의 기본 · D 플립플롭

"기억하는 회로"의 최소 단위: D-FF

D 플립플롭(D-FF)은 1비트를 기억하는 가장 작은 저장소입니다. 클럭이 올라오는 순간 입력 d를 붙잡아 출력 q로 내보내고, 다음 클럭까지 그 값을 유지합니다.

module dff (
  input  clk, rst_n, d,
  output reg q
);
  always @(posedge clk) begin
    if (!rst_n) q <= 1'b0; // 리셋
    else       q <= d;    // 저장
  end
endmodule
rst_n은 "0일 때 리셋"이라는 active-low 리셋 신호입니다. 이 코드는 클럭 상승 엣지에서만 리셋을 확인하는 동기 리셋(synchronous reset)이며, 클럭과 무관하게 즉시 리셋하려면 always @(posedge clk or negedge rst_n)처럼 rst_n을 감도 리스트에 넣는 비동기 리셋으로 씁니다.
가장 자주 묻는 규칙

blocking = vs non-blocking <=

blocking =non-blocking <=
실행위→아래 순차, 즉시 반영오른쪽 값 먼저 다 읽고, 동시에 대입
비유x = x + 1 (일반 변수)모든 갱신이 한 박자에 동시 발생
쓰는 곳조합 @(*)순차 @(posedge clk)

철칙: 순차 회로(클럭 블록)엔 non-blocking <=, 조합 회로엔 blocking =.

왜 순차엔 <=일까? 실제 플립플롭들은 클럭 엣지에 전부 동시에 갱신됩니다. <=가 바로 그 "동시 갱신"을 흉내 냅니다.

// 시프트 레지스터 (a→b→c)
always @(posedge clk) begin
  b <= a;   // 옛 a값으로
  c <= b;   // 옛 b값으로 (동시!)
end

만약 여기서 =를 쓰면 b=a가 먼저 반영돼 c=b가 새 b(=a)를 받습니다 → 시프트가 무너지고 시뮬과 실제 칩이 달라지는 악명 높은 버그가 납니다.

계층 · 인스턴스화

작은 module을 조립해 큰 회로를 만든다

큰 설계는 작은 module들을 인스턴스화(instantiation)해서 조립합니다. 클래스를 정의하고 new로 객체를 여러 개 만드는 것과 정확히 같습니다.

// dff를 2개 박아 2비트 레지스터
module reg2 (input clk, rstn,
  input [1:0] d, output [1:0] q);

  dff u0 (.clk(clk), .rst_n(rstn),
          .d(d[0]), .q(q[0])); // 인스턴스1
  dff u1 (.clk(clk), .rst_n(rstn),
          .d(d[1]), .q(q[1])); // 인스턴스2
endmodule
  • dff = 클래스 정의(설계도)
  • u0, u1 = 인스턴스 이름(객체)
  • .clk(clk) = 포트를 이름으로 연결(named port) — 위치 순서보다 이름 연결을 권장

이렇게 만들어진 module 계층 트리가 곧 검증할 때 신호를 찾아가는 경로(top.reg2.u0.q)가 됩니다. 파일·폴더 트리에서 경로 찾는 것과 같죠.

4-state 값 체계

비트는 0/1만이 아니다 — 0 · 1 · x · z

SW의 bool은 true/false 2개뿐이지만, Verilog의 1비트는 4가지 상태를 가질 수 있습니다. 디버깅의 단서가 되는 핵심 개념입니다.

0️⃣ 0

논리 0 (Low)

1️⃣ 1

논리 1 (High)

❓ x

unknown — 값을 모름/충돌. 초기화 안 됨, 또는 두 드라이버가 0·1을 동시에 밀어 충돌.

🔌 z

high-impedance — 아무도 안 미는 "둥둥 뜬" 상태. 핀이 연결 안 됨, 또는 tri-state 버스.

x는 SW의 초기화 안 된 변수 / NaN 같은 느낌입니다. 시뮬레이션에서 x가 줄줄이 퍼지면 "어딘가 리셋이나 초기화가 빠졌다"는 강력한 버그 신호죠.

주의: x는 시뮬레이터의 표현일 뿐, 실제 칩엔 0이나 1만 존재합니다. 그래서 x가 실제 칩에선 예측할 수 없는(불확정한) 0이나 1로 굳어져 위험합니다 — 검증에서 x 추적이 중요한 이유입니다.
합성 가능 · synthesizable

"칩이 되는 코드" vs "시뮬레이션에서만 도는 코드"

Verilog 코드는 두 종류로 나뉩니다. 합성 도구가 실제 게이트로 바꿀 수 있는 코드(설계)와, 검증용으로 시뮬레이터에서만 도는 코드(테스트벤치).

구분Synthesizable (설계, DUT)시뮬 전용 (테스트벤치)
목적실제 회로가 됨회로를 두드려 검증
예assign, 클럭 always, moduleinitial, #10(딜레이), $display, $finish
제약실물 회로로 그릴 수 있어야 함제약 없음, C처럼 자유

왜 중요? #10 같은 시간 지연이나 $display는 어떤 합성에서도 게이트로 만들 수 없어 합성되지 않습니다. initial 블록도 ASIC 합성에서는 무시/오류가 되지만, FPGA(Vivado·Quartus 등)에서는 레지스터 초기값처럼 일부 파워업 상태로 합성에 반영되기도 합니다. 설계자가 실수로 이런 걸 DUT에 넣으면 "시뮬은 통과했는데 칩은 다르게 동작"하는 사고가 납니다. 검증 엔지니어가 잡아내야 할 대표적 함정입니다.

면접 예상 질문

이렇게 물어보면, 이렇게 답한다

wire와 reg의 차이는?
wire는 전선처럼 연결만 하며 assign으로 값을 받고, reg는 값을 담는 변수로 always 블록 안에서 값을 받습니다. 단, reg가 곧 레지스터(기억소자)는 아닙니다 — 실제 플립플롭이 되는지는 @(posedge clk) 사용 여부로 결정됩니다.
blocking과 non-blocking은 언제 쓰나요?
조합 회로(always @(*))에는 blocking =, 순차 회로(always @(posedge clk))에는 non-blocking <=를 씁니다. 실제 플립플롭들이 클럭 엣지에 동시에 갱신되는 동작을 <=가 정확히 모델링하기 때문이고, 섞어 쓰면 시뮬레이션과 실제 칩 동작이 달라지는 레이스 버그가 생깁니다.
x와 z는 무엇인가요?
x는 unknown(값을 모름/충돌)으로 초기화 누락이나 다중 드라이버 충돌에서 나오고, z는 high-impedance로 아무도 구동하지 않는 떠 있는 상태입니다. 실제 칩엔 0/1만 있으므로 x가 퍼지면 초기화·리셋 버그의 신호로 보고 추적합니다.
synthesizable 코드란?
합성 도구가 실제 게이트 회로로 변환할 수 있는 코드입니다. initial, #delay, $display 같은 시뮬 전용 구문은 합성되지 않으며 테스트벤치에서만 씁니다. 설계(DUT)는 반드시 합성 가능한 부분집합으로 작성해야 합니다.
핵심 요약

이 챕터, 한 손에 잡기

  • Verilog는 HDL — 회로를 글로 기술, 모든 블록이 병렬
  • module=함수/클래스, 인스턴스화=객체 생성, port=입출력
  • assign=조합(즉시 바인딩), wire로 받음
  • always @(*)=조합, @(posedge clk)=순차(콜백), reg로 받음
  • 순차엔 non-blocking <=, 조합엔 blocking =
  • 값은 4-state 0/1/x/z, 설계는 synthesizable해야

"Verilog는 회로를 텍스트로 기술하는 HDL이고, assign은 조합·always@posedge는 순차이며 순차에는 non-blocking 대입을 씁니다."

— 이 한 문장이면 Verilog 기본 질문의 90%를 막습니다.
