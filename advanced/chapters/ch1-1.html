기준 스펙: IEEE 1364-2005 (Verilog HDL) — §9.2 blocking/non-blocking, §11(현 1800에선 §4) stratified event queue. 시뮬레이터(Verilator 제외 이벤트형)·합성기(Design Compiler 등)는 이 표준 위에서 동작합니다. 면접에서 "Verilog 좀 봤다"와 "RTL 써봤다"를 가르는 건 이 디테일입니다.

합성가능 RTL ①

동기 카운터 — 정석 템플릿

module counter #(parameter WIDTH = 8) (
    input  wire              clk,
    input  wire              rst_n,   // active-low 비동기 리셋
    input  wire              en,
    output reg [WIDTH-1:0] cnt
);
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)      cnt <= {WIDTH{1'b0}};  // 리셋 분기 먼저
        else if (en)     cnt <= cnt + 1'b1;        // 순차 → NBA(<=)
    end
endmodule

// 클럭드 always = 플립플롭. 비동기 리셋은 sensitivity에 negedge rst_n 포함, 본문 첫 분기로.

순차회로(레지스터 생성)의 합성 템플릿은 딱 정해져 있습니다: always @(posedge clk ...) + 대입은 전부 non-blocking(<=). en이 false면 cnt는 현재값 유지(else가 없어 대입이 일어나지 않음) — 이건 의도된 enable 동작이지 latch가 아닙니다(이미 FF이므로).

= vs <= ①

blocking vs non-blocking — 무엇이 다른가

항목blocking =non-blocking <=
실행 시점즉시 계산·즉시 대입(순차적)RHS는 즉시 평가, LHS 대입은 NBA 영역에서 한꺼번에
같은 블록 내다음 줄이 새 값을 봄다음 줄도 옛 값을 봄(병렬)
모델링 대상조합논리·테스트벤치 임시변수순차논리(FF)
직관적 그림칠판에 적힌 값을 그 자리에서 지우고 새로 씀모든 우변값을 먼저 메모해 두고 → 사이클 끝에 한꺼번에 옮겨 적음

<=는 "이번 사이클의 입력은 전부 직전 값으로 고정해서 읽고, 출력은 사이클 끝에 한꺼번에 반영"한다고 보면 됩니다. 마치 시험 답을 모두 연습장에 적어둔 뒤 종료 직전에 답안지에 동시에 옮기는 것과 같아서, 두 FF이 서로의 값을 맞바꾸는(swap) 동작도 자연스럽게 됩니다.

= vs <= ②

실전 함정 — shift register race

// ❌ blocking: q2가 d를 즉시 봄 → 1-stage로 축소
always @(posedge clk) begin
    q1 = d;     // q1 즉시 갱신
    q2 = q1;    // 방금 바뀐 q1(=d)을 봄!
end           // 결과: q2 == d, FF 1개처럼 동작
// ✅ non-blocking: RHS는 옛 값 → 2-stage shift
always @(posedge clk) begin
    q1 <= d;    // RHS=옛 d
    q2 <= q1;   // RHS=옛 q1 (이번 갱신 전)
end           // 결과: 정상 2단 시프트 q2←q1←d

순차회로에 blocking을 쓰면 두 가지 사고가 납니다.
① 위처럼 줄 순서에 따라 의도와 다른 회로(시프트가 사라짐). ② 같은 신호를 여러 always가 blocking으로 건드리면 시뮬레이터 실행 순서에 따라 결과가 달라지는 race — 시뮬은 통과해도 합성 후 게이트와 불일치.

규칙은 단순합니다: 순차=<= / 조합== / 둘을 한 always에 섞지 말 것. 거의 모든 RTL 린트(lint)가 이 위반을 잡습니다.
왜 race가 생기나

Verilog 이벤트 스케줄링 — 4개 영역

같은 시뮬레이션 시각(time slot) 안에서도 이벤트는 정해진 영역 순서로 처리됩니다(stratified event queue). 이 순서가 <=의 동작을 보장합니다.

③ NBA(Non-Blocking Assignment update) 영역이 핵심입니다.

  • posedge에서 모든 always의 <= RHS는 Active에서 먼저 전부 평가(옛 값을 그대로 떠 둠).
  • 실제 LHS 대입은 NBA 영역에서 일괄 수행 → 같은 슬롯의 다른 블록이 옛 값을 본다.
  • 이 분리 덕분에 FF 간 값 교환·시프트가 실행 순서와 무관하게 항상 같은 결과로 결정됩니다.
합성가능 RTL ②

FSM — 3-always 정석 템플릿

localparam [1:0] IDLE=2'd0, RUN=2'd1, DONE=2'd2;
reg [1:0] state, next;

// (1) 상태 레지스터 — 순차 → NBA
always @(posedge clk or negedge rst_n)
    if (!rst_n) state <= IDLE;
    else       state <= next;

// (2) 다음상태 논리 — 조합 → blocking, default 필수
always @(*) begin
    next = state;                 // ★ latch 방지: 기본값 먼저
    case (state)
        IDLE: if (start) next = RUN;
        RUN:  if (done)  next = DONE;
        DONE:            next = IDLE;
        default:         next = IDLE;  // x-상태 복구
    endcase
end

// (3) 출력 논리(Moore) — 조합
always @(*) busy = (state == RUN);

(2)에서 기본값(next=state)이나 default가 빠지면 어떤 입력 조합에서 next가 대입되지 않아 latch가 추론됩니다 — 다음 슬라이드에서 정밀히.

조합논리의 1번 사고

Latch 추론 — 원인과 방어

조합 always는 모든 입력 조합에서 출력이 항상 대입되어야 순수 조합으로 합성됩니다. 한 경로라도 대입이 빠지면 합성기는 "이전 값을 기억"해야 하므로 의도치 않은 latch를 추론합니다.

// ❌ else 없음 → y가 a==0일 때 미대입 → LATCH
always @(*) if (a) y = b;

// ✅ 모든 경로 대입 → 순수 MUX
always @(*) if (a) y = b; else y = c;

3대 원인

  • if에 else 누락
  • case에 default 누락 + 비완전(non-full) 분기
  • 다출력 블록에서 일부 출력만 대입

방어: 블록 맨 위에 모든 출력 기본값 대입 → 그 뒤 조건부 덮어쓰기.

latch는 시뮬에선 멀쩡해 보이지만 정적 타이밍(STA)이 불가하고 글리치에 취약합니다. 합성 리포트의 Inferred latch 경고는 거의 항상 버그 신호입니다.

sensitivity & 4-state

always @(*) 와 0/1/x/z

sensitivity list

  • always @(*)(또는 @*): 우변에 읽히는 모든 신호 자동 포함 → 누락 버그 차단. 조합 표준.
  • 수동 리스트(@(a or b))에서 신호 하나 빠지면 시뮬↔합성 불일치(시뮬은 안 깨어남, 합성은 다 본다).
  • 순차는 @(posedge clk or negedge rst_n)처럼 엣지만 나열.

4-state 값

값의미
0 / 1논리 로우/하이
xunknown(미초기화·충돌·경합)
zhigh-Z(미구동·tri-state)
reg는 4-state. x는 "아무 값"이 아니라 "모름"이라 비교 ==가 x를 내기도. x-propagation 추적이 디버깅의 큰 부분입니다.

signed 함정: 기본 reg/wire는 unsigned. 산술 비교·shift에서 부호가 필요하면 reg signed로 선언해야 하며, 한 피연산자라도 unsigned면 식 전체가 unsigned로 평가됩니다.

파라미터화 & 반복

generate · genvar · $clog2

parameter N = 8;
localparam AW = $clog2(N);   // 8 → 3비트 (주소폭 자동 산출)

genvar i;
generate
    for (i = 0; i < N; i = i + 1) begin : g_ff   // 이름표 필수
        dff u_dff (.clk(clk), .d(din[i]), .q(dout[i]));
    end
endgenerate

// generate-for는 동작 중에 도는 반복이 아니라, 회로를 만들 때 "같은 하드웨어 블록 N개를 그대로 복제해 펼치는" 구조다.

  • generate: 하드웨어 반복 인스턴스화·조건부 생성(if/case). genvar는 상수 인덱스 전용.
  • parameter: 인스턴스마다 override 가능(#(.N(16))). localparam: override 불가, 내부 파생 상수.
  • $clog2(n): ⌈log₂ n⌉ — N개를 가리킬 비트수. $clog2(8)=3, $clog2(9)=4.

$clog2 경계 함정: $clog2(1)=0, $clog2(8)=3이지만 0~8(9개 값)을 표현하려면 $clog2(9)=4비트가 필요합니다. "N개 카운트의 최댓값 N-1"인지 "N까지 세는지"를 헷갈리면 1비트 off-by-one이 납니다.

case의 위험한 변형

casez · casex · full/parallel_case

구문와일드카드위험
case없음(완전 일치, x/z도 그대로 비교)안전 — 기본 선택
casezz와 ?를 don't-care로비교적 안전(? 권장)
casexx·z·? 모두 don't-care위험 — 실제 x가 와일드매칭

casex의 함정: 셀렉트에 미초기화 x가 끼면 그 비트가 아무 분기에나 매칭되어, RTL 시뮬은 우연히 통과하고 합성된 게이트는 다르게 동작 → x-blindness 버그. 디코더엔 casez(와일드카드 ?)를 쓰세요.

full_case/parallel_case(합성 pragma)는 합성기에게 "모든 케이스 커버됨/상호배타적"이라고 약속하는 것. 실제로 안 그러면 시뮬과 합성 결과가 갈라집니다. 권장: pragma 대신 default와 명시적 분기로 같은 효과를 내라.

이 함정들을 어떻게 잡나

🧹 정적(코드 안 돌리고)

  • Lint(Spyglass/Verilator -Wall): blocking-in-seq, 불완전 case, 누락 sensitivity, 폭 불일치 검출
  • CDC 분석은 별도지만 같은 흐름

📐 동적(시뮬·정형)

  • SVA assertion: $rose(req) |-> ##[1:3] ack 같은 시간 속성 검증
  • Coverage: FSM 상태/전이 커버, case 분기 커버
  • X-prop 모드로 x-pessimism/optimism 노출
// SVA: 모든 case 진입 시 latch 없이 단일 사이클 결과 보장 예
assert property (@(posedge clk) disable iff(!rst_n)
    (state inside {IDLE,RUN,DONE}));   // 미정의 상태 진입 금지

"시뮬은 통과하는데 실리콘에서 깨지는" 1순위가 blocking race·latch·x-blind case입니다. 그래서 lint를 0 violation으로 유지하고 회귀에 SVA를 상시 켭니다.

면접 심화 질문

여기까지 답하면 "RTL 써본 사람"으로 보인다

non-blocking 대입은 이벤트 큐의 어느 영역에서 적용되나요?
<=의 RHS는 Active 영역에서 즉시 평가되지만, LHS 대입은 같은 time slot의 NBA(Non-Blocking Assignment) 영역에서 일괄 수행됩니다. 영역 순서는 Active → Inactive → NBA → Postponed이고, 이 분리 덕에 같은 클럭에서 FF끼리 옛 값을 보며 race 없이 결정적으로 갱신됩니다.
왜 순차회로엔 non-blocking, 조합엔 blocking인가요?
순차는 모든 FF이 같은 엣지에 동시에 옛 값으로 갱신돼야 실제 하드웨어와 맞습니다. <=는 RHS(옛 값)를 먼저 떠 둔 뒤 NBA에서 일괄 대입해 이 동시성과 실행순서 독립성을 보장합니다. 조합은 한 always 안에서 임시값이 즉시 전파돼야 하므로 =가 맞고, 둘을 섞으면 race·합성불일치가 납니다.
latch는 왜 추론되며 casex는 왜 피하나요?
latch는 조합 always에서 어떤 입력 경로에 출력 대입이 빠질 때(else/default 누락, 일부 출력만 대입) 합성기가 값을 기억해야 해서 생깁니다. 방어는 블록 상단 기본값 대입입니다. casex는 셀렉트의 x까지 don't-care로 와일드매칭해, 미초기화 x가 엉뚱한 분기에 걸려 시뮬↔합성 불일치를 만들므로 ? 기반 casez를 씁니다.
핵심 요약

Verilog 정밀 — 한 손에

  • 순차=<=(NBA), 조합==, 한 always에 섞지 말 것
  • 이벤트 큐: Active → Inactive → NBA → Postponed
  • 조합 always는 @(*) + 모든 경로 대입 → latch 방지
  • latch 원인: else/default/일부출력 누락
  • generate=HW 복제, $clog2(N)=비트폭, localparam≠override
  • casex 위험(x 와일드매칭) → casez/?, pragma보다 default
  • 4-state(0/1/x/z), reg는 기본 unsigned

"RTL은 동시 실행 하드웨어이고, <=의 NBA 스케줄링이 그 동시성을 보장합니다. 순차 non-blocking · 조합 full-case 기본값으로 race와 latch를 막고, lint와 SVA로 검증합니다."
