기준 스펙: 본 챕터는 ARM AMBA APB Protocol Specification을 따릅니다. 버전 표기는 흔히 APB2 / APB3(AMBA 3 APB) / APB4(AMBA 4 APB)로 부릅니다. 핵심 변화: PREADY·PSLVERR은 APB3부터, PSTRB·PPROT은 APB4부터입니다. 이 경계가 면접 단골입니다.

전체 신호 · 방향 · 도입 버전

APB 신호 전수표 — 방향과 폭까지

버스는 전선 묶음 + 약속입니다. "M→S"는 마스터(보통 브리지)가 구동, "S→M"은 슬레이브가 구동. 폭 n은 데이터 버스 바이트 수(예: 32비트면 n=4).

신호방향폭의미도입
PCLK—1버스 클럭. 모든 신호는 PCLK 상승엣지 기준.APB2
PRESETn—1리셋, active-low(0일 때 리셋).APB2
PADDRM→S≤32주소(바이트 주소).APB2
PSELM→S1이 슬레이브 선택. 디코더가 주소로 생성.APB2
PENABLEM→S1ACCESS 페이즈 표시(2번째 클럭부터 1).APB2
PWRITEM→S11=쓰기, 0=읽기.APB2
PWDATAM→S8/16/32쓰기 데이터(PWRITE=1일 때 유효).APB2
PRDATAS→M8/16/32읽기 데이터(PWRITE=0, PREADY=1일 때 유효).APB2
PREADYS→M1슬레이브 준비/완료. 0이면 wait state.APB3
PSLVERRS→M1에러 응답. 전송 완료 클럭에만 유효.APB3
PSTRBM→Sn바이트 strobe. PSTRB[k]=1이면 그 바이트 기록.APB4
PPROTM→S3보호 속성(권한/보안/명령-데이터).APB4
접두사 P는 "Peripheral 버스 신호"라는 표식입니다. 예: PSLVERR = P + SLV(Slave) + ERR. PRESETn의 n은 active-negative(저레벨 활성)을 뜻합니다.
상태머신 · 정확한 비트값

IDLE / SETUP / ACCESS — PSEL·PENABLE을 숫자로

개념판에선 "흐름"을, 여기선 각 상태에서 두 신호의 정확한 값을 외웁니다. 면접에서 가장 자주 빗나가는 지점입니다.

상태PSELPENABLE지속이 클럭에 하는 일
IDLE00가변대기. 버스 비선택.
SETUP10정확히 1클럭PADDR/PWRITE/PWDATA(+PSTRB/PPROT) 구동, 슬레이브 깨움.
ACCESS111클럭 이상실제 전송. PREADY=1 될 때까지 유지.

SETUP: PSEL=1, PENABLE=0 — 무조건 1클럭만 머뭅니다. ACCESS: PSEL=1, PENABLE=1 — PREADY가 1로 샘플될 때까지 머뭅니다. 즉 PENABLE은 "거래의 두 번째 클럭"이 됐다는 신호이며, SETUP에서 ACCESS로 갈 때 0→1로 정확히 한 번 토글합니다.

흔한 오답: "SETUP에서 PENABLE=1". 실제 SETUP은 PENABLE=0이고, ACCESS에서 비로소 1이 됩니다. 또 "PENABLE이 여러 클럭 깜빡인다" — 아닙니다. ACCESS 동안 PENABLE은 계속 1로 유지되고, 전송이 끝나면(=PREADY=1) 다음 거래의 SETUP 또는 IDLE로 갑니다.

타이밍 파형 · 읽기/쓰기 + wait state

파형으로 박자 맞추기

아래는 SETUP 1클럭 → ACCESS에서 PREADY=0으로 wait state 1회가 삽입된 트랜잭션입니다. 쓰기/읽기 데이터가 유효한 창과 PSLVERR 샘플 지점을 표시했습니다.

읽는 법: T1(SETUP) PENABLE=0으로 주소/데이터 세팅 → T2(ACCESS 시작) PENABLE=1, 그러나 PREADY=0이라 멈춤(wait) → T3 PREADY=1로 전송 완료. 읽기에서는 이 T3 클럭의 PRDATA만 유효하고, 쓰기/읽기 모두 PSLVERR도 T3에서만 의미가 있습니다.

에러·바이트·보호 신호 정밀

PSLVERR · PSTRB · PPROT을 비트로

PSLVERR (APB3~): 에러 응답. 샘플 유효 조건은 단 하나 — PSEL=1 && PENABLE=1 && PREADY=1인 클럭(=전송이 실제로 완료되는 박자). 그 외 클럭의 PSLVERR 값은 의미 없음(don't-care). 1이면 그 트랜잭션 실패(잘못된 주소, 권한 위반, 읽기 전용에 쓰기 등). 에러여도 트랜잭션 자체는 그 클럭에 "완료"됩니다.

PPROT[2:0] (APB4~) 보호 속성:

비트01
PPROT[0]NormalPrivileged
PPROT[1]SecureNon-secure
PPROT[2]DataInstruction

PSTRB (APB4~): 쓰기 바이트 strobe. 폭은 데이터 바이트 수 n. PSTRB[k]=1이면 PWDATA[8k+7:8k] 바이트를 기록, 0이면 그 바이트는 무시. 부분 쓰기(예: 32비트 워드 중 하위 1바이트만)에 사용합니다.

// 32-bit, n=4. 하위 2바이트만 기록
PWDATA  = 32'hDEAD_BEEF;
PSTRB   = 4'b0011;  // [0],[1]=1
// 결과: mem[1:0] <= BEEF, [3:2] 보존

규칙: PSTRB는 쓰기에서만(PWRITE=1) 유효. 읽기(PWRITE=0)에서는 모든 PSTRB 비트를 0으로 두어야 합니다.

함정: "PSLVERR=1이면 데이터가 안 들어온다"가 아니라 — 전송은 완료되되 에러로 표시됩니다(읽기면 PRDATA는 보통 무의미). 또 "PPROT[1]=1이 Secure"는 오답: PPROT[1]=1은 Non-secure입니다(AXI의 AxPROT과 동일한 반전 규칙).

합성 가능한 슬레이브 FSM

APB Slave를 Verilog로 — 핵심만

슬레이브 관점에서 본 최소 구현입니다. 포인트는 setup_phase / access_phase 판별과 PREADY로 wait state 만들기입니다.

module apb_slave // 32-bit data, APB4 (
  input             PCLK, PRESETn,
  input             PSEL, PENABLE, PWRITE,
  input      [11:0] PADDR,
  input      [31:0] PWDATA,
  input      [ 3:0] PSTRB,
  output reg [31:0] PRDATA,
  output            PREADY,
  output            PSLVERR
);
  // access 페이즈 = 선택됐고 PENABLE=1인 클럭
  wire access = PSEL & PENABLE;
  wire wr_en  = access & PWRITE & PREADY;
  wire rd_en  = access & ~PWRITE;

  reg [31:0] regfile [0:15];

  // 이 예: 항상 1클럭에 완료 → wait state 없음
  assign PREADY  = 1'b1;
  // 주소가 범위를 벗어나면 에러 (전송 완료 클럭에만 평가됨)
  assign PSLVERR = access & PREADY & (PADDR[11:6] != 6'd0);

  integer b;
  always @(posedge PCLK) if (wr_en)
    for (b=0; b<4; b=b+1)
      if (PSTRB[b])                    // 바이트 strobe 반영
        regfile[PADDR[5:2]][8*b +: 8] <= PWDATA[8*b +: 8];

  always @(*) PRDATA = rd_en ? regfile[PADDR[5:2]] : 32'h0;
endmodule
// access = PSEL & PENABLE 가 ACCESS 페이즈 판별식. wait state가 필요하면 PREADY를 카운터로 몇 클럭 0으로 유지하면 됩니다.

함정: 쓰기 인에이블을 access & PWRITE로만 만들면 wait state 동안 같은 데이터를 여러 번 기록합니다. 반드시 & PREADY를 곱해 "완료되는 클럭에 한 번만" 써야 합니다.

버전 경계 · 면접 단골

APB2 → APB3 → APB4, 무엇이 추가됐나

APB는 시간이 지나며 신호가 추가됐을 뿐, 기본 골격(2페이즈·비파이프라인·무버스트)은 그대로입니다. 무엇이 어느 버전에 들어왔는지 정확히 구분하세요.

버전대표 추가의미
APB2기본 신호 일체PSEL/PENABLE/PADDR/PWRITE/PWDATA/PRDATA. 고정 2클럭 전송(wait 불가).
APB3PREADY · PSLVERRwait state(가변 길이 전송)와 에러 응답 도입. "느린 슬레이브"가 비로소 표현 가능.
APB4PSTRB · PPROT바이트 단위 부분 쓰기와 보호 속성(권한/보안/명령) 도입.

정리 한 줄: PREADY/PSLVERR이 보이면 최소 APB3, PSTRB/PPROT이 보이면 APB4. 반대로 어떤 IP가 "PREADY가 없다"면 APB2 슬레이브이며, 항상 정확히 2클럭에 끝납니다(브리지가 wait를 줄 수 없음).

개발자 비유: APB2는 타임아웃 없는 동기 호출(서버가 무조건 정해진 시간에 답한다고 가정), APB3의 PREADY는 서버가 "처리 중, 잠깐만요"라고 backpressure를 거는 것, PSLVERR은 HTTP 5xx 상태코드, PSTRB는 PATCH의 부분 필드 업데이트에 가깝습니다.

구조적 한계 · 브리지

비파이프라인·무버스트, 그래서 브리지가 필요하다

APB는 한 트랜잭션이 완전히 끝나야 다음이 시작됩니다(겹침 없음). 버스트도 없어 한 번에 1워드만 옮깁니다. 그래서 고속 버스(AXI/AHB)의 요청을 브리지가 APB 2페이즈 핸드셰이크로 변환해 느린 주변장치에 전달합니다.

  • 비파이프라인: outstanding 거래 항상 1개
  • 무버스트: AxLEN 같은 길이 개념 없음
  • 단일 채널: 주소·데이터 분리 채널 없음

브리지 역할: ① 상위 버스의 버스트를 여러 개의 단일 APB 전송으로 분해, ② 매 전송마다 SETUP(1클럭)+ACCESS(PREADY 대기) 시퀀스 구동, ③ APB의 PSLVERR을 상위 버스의 응답코드(예: AXI RRESP/BRESP의 SLVERR)로 변환.

검증 엔지니어의 시선

이 프로토콜, 어떻게 검증하나

APB는 단순해서 프로토콜 체크 = 어서션, 정확성 = 스코어보드, 빈틈 = 커버리지로 깔끔히 나뉩니다. UVM APB VIP(agent: driver/monitor/sequencer)가 표준 접근입니다.

// SVA: SETUP 다음 클럭은 반드시 ACCESS
property p_setup_to_access;
  @(posedge PCLK) disable iff(!PRESETn)
  (PSEL && !PENABLE)
     |=> (PSEL && PENABLE);
endproperty
a_s2a: assert property(p_setup_to_access);

// PADDR은 ACCESS 동안 안정(변하면 안 됨)
a_addr_stable: assert property(@(posedge PCLK)
  (PSEL && PENABLE && !PREADY)
     |=> $stable(PADDR));
  • 어서션: SETUP→ACCESS 전이, ACCESS 중 PADDR/PWDATA/PWRITE $stable, PENABLE은 SETUP에서 0.
  • 스코어보드: 쓰기 후 같은 주소 읽기 = mirror 비교(PSTRB 반영).
  • 커버리지 코너: PREADY=0 wait 0/1/N클럭, PSLVERR=1, 읽기와 쓰기, PSTRB 전 패턴(0000~1111), back-to-back 전송.
  • 리셋 중 PSEL/PENABLE=0 확인.

VIP 모니터는 PREADY=1 클럭에만 PRDATA/PSLVERR을 캡처해야 합니다 — 그 외 클럭 값은 don't-care이므로 비교하면 거짓 실패가 납니다.

검증 함정: wait state 커버리지를 빼먹으면 PREADY=0 경로가 한 번도 안 돌아 슬레이브의 멈춤 로직 버그를 놓칩니다. 또 어서션을 disable iff(!PRESETn)로 감싸지 않으면 리셋 직후 거짓 위반이 쏟아집니다.

면접 심화 질문

여기까지 답하면 실무자로 보인다

SETUP과 ACCESS에서 PSEL·PENABLE 값을 정확히 말해보세요.
SETUP: PSEL=1, PENABLE=0 — 항상 정확히 1클럭이며 이때 PADDR/PWRITE/PWDATA(APB4면 PSTRB/PPROT)를 구동합니다. ACCESS: PSEL=1, PENABLE=1 — PREADY=1로 샘플될 때까지 PENABLE을 1로 유지합니다. IDLE은 PSEL=0, PENABLE=0. PENABLE은 SETUP→ACCESS에서 0→1로 한 번만 토글합니다.
PREADY로 wait state는 어떻게 만들고, 몇 클럭까지 가능합니까?
ACCESS 페이즈에서 슬레이브가 PREADY=0으로 두면 마스터가 그 클럭에 전송을 끝내지 못하고 PENABLE=1을 유지한 채 대기합니다(wait state). 슬레이브가 준비되면 PREADY=1을 띄우고 그 클럭에 전송 완료. 클럭 수 상한은 프로토콜상 정해져 있지 않으며 슬레이브가 임의로 늘릴 수 있습니다(실무에선 watchdog/timeout으로 보호). PREADY는 APB3부터 존재하고, APB2는 항상 고정 2클럭이라 wait가 불가능합니다.
PSLVERR은 언제 유효하고, PSTRB와 함께 APB 버전 차이를 설명하면?
PSLVERR은 PSEL=1·PENABLE=1·PREADY=1이 모두 성립하는 전송 완료 클럭에만 유효하며, 그 외 클럭 값은 don't-care입니다. 1이면 해당 트랜잭션 실패(잘못된 주소·권한 위반 등). PSLVERR과 PREADY는 APB3에서 도입됐고, PSTRB(쓰기 바이트 strobe, PSTRB[k]→PWDATA의 k번째 바이트)와 PPROT(보호 속성)는 APB4에서 추가됐습니다. PSTRB는 PWRITE=1에서만 유효하고 읽기 땐 0으로 둡니다.
핵심 요약

이 심화 챕터, 숫자로 한 손에

  • IDLE PSEL=0/PEN=0 · SETUP PSEL=1/PEN=0(1클럭) · ACCESS PSEL=1/PEN=1(PREADY까지)
  • wait state = ACCESS 중 PREADY=0 유지, 길이 무제한
  • PSLVERR은 PSEL·PENABLE·PREADY=1인 단 한 클럭만 유효
  • 버전: PREADY/PSLVERR=APB3, PSTRB/PPROT=APB4
  • PPROT[1]=1=Non-secure(반전 주의), PSTRB는 쓰기 전용
  • 비파이프라인·무버스트 → AXI/AHB→APB 브리지로 연결

"APB는 SETUP(PEN=0)·ACCESS(PEN=1) 2페이즈 동기 버스로, PREADY로 wait state를, 전송 완료 클럭의 PSLVERR로 에러를 표현합니다. PREADY/PSLVERR은 APB3, PSTRB/PPROT은 APB4 추가."
