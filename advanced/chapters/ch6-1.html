JTAG, 16-상태 TAP에서 DAP까지

개념판에서 "디버그 포트"를 잡았다면, 이제 면접관이 파고드는 곳 — TAP 16-상태 FSM, TMS로 한 비트씩 이동, BYPASS/IDCODE/EXTEST 인코딩, 1687 SIB 재구성, JTAG2APB·CoreSight DAP 트랜잭션까지 정확히 내려갑니다.

이 챕터의 목표

"4핀 디버그 포트"에서 "신호·인코딩·트랜잭션"으로

✅ 개념판에서 한 것

  • JTAG = 칩 안을 들여다보는 직렬 디버그 인터페이스
  • 4개 핀(TCK/TMS/TDI/TDO)으로 스캔체인 접근
  • BYPASS/IDCODE 같은 명령이 있다는 큰 그림
  • boundary scan으로 핀을 외부에서 흔든다

🎯 심화판에서 더할 것

  • TAP 16-상태 FSM 정확한 전이(TMS 0/1로 이동)
  • 명령 인코딩: BYPASS=전부 1, IDCODE, SAMPLE/PRELOAD, EXTEST, INTEST
  • IR/DR 길이·boundary cell 동작
  • iJTAG 1687: SIB·ICL/PDL·instrument 네트워크 재구성
  • JTAG2APB / CoreSight DAP: DPACC·APACC, SWD 대안

기준 스펙: IEEE 1149.1(boundary scan / TAP) · IEEE 1687-2014(iJTAG, embedded instrument 접근) · Arm CoreSight DAP(ADIv5/ADIv6, DP/AP). 면접에서 "JTAG 안다"와 "다뤄봤다"를 가르는 건 TAP 상태 시퀀스를 손으로 그릴 수 있는가입니다.

물리 신호

TCK · TMS · TDI · TDO (+ TRST) — 4(+1)핀

신호방향역할
TCK입력Test Clock — 모든 동작의 기준 클럭. TMS/TDI는 상승엣지에 샘플, TDO는 하강엣지에 출력(스큐 회피)
TMS입력Test Mode Select — TAP FSM을 움직이는 단 하나의 제어선. 매 TCK마다 0/1로 상태 전이
TDI입력Test Data In — 선택된 레지스터(IR 또는 DR)로 직렬 입력
TDO출력Test Data Out — 레지스터에서 직렬 출력. Shift 상태에서만 구동(그 외 Hi-Z)
TRST입력(옵션)Test Reset — 비동기 active-low 리셋. 옵션 핀(없어도 됨)

TRST가 없어도 리셋 가능: TMS=1을 5 TCK 연속 인가하면 어떤 상태에서든 Test-Logic-Reset로 들어갑니다(FSM 구조가 이를 보장). 그래서 TRST는 1149.1에서 선택 핀입니다.

흔한 오답: "TDO도 매 클럭 데이터를 낸다" ❌ → TDO는 Shift-IR/Shift-DR 상태에서만 active, 나머지 상태에선 Hi-Z(고임피던스)라 여러 TAP를 체인으로 묶을 수 있습니다.

★ 면접 핵심 ★

TAP 상태머신 — 정확히 16 상태

좌측 리셋/유휴 2칸 + DR 열 7칸 + IR 열 7칸 = 16 상태. 두 열은 구조가 똑같고, 분기점이 Select-DR/Select-IR입니다.

핵심 경로: RTI →(1)→ Select-DR →(0)→ Capture-DR →(0)→ Shift-DR →(여기서 0을 N번 = N비트 시프트)→ Exit1-DR →(1)→ Update-DR. IR 열도 완전히 동일한 형태입니다.
상태를 표로 못박기

Capture · Shift · Exit1 · Pause · Exit2 · Update

상태TMS=0 다음TMS=1 다음그 상태가 하는 일
Capture-DR/IRShiftExit1레지스터에 병렬 로드(IR은 보통 …01 고정 패턴 캡처)
Shift-DR/IRShift(루프)Exit1TDI→레지스터→TDO로 1비트/클럭 직렬 시프트
Exit1-DR/IRPauseUpdate시프트 종료 분기점
Pause-DR/IRPause(루프)Exit2시프트 일시정지(버퍼 채울 시간 확보)
Exit2-DR/IRShift(재개)Update시프트 재개 or 종료
Update-DR/IRRun-Test/IdleSelect-DR섀도 래치를 병렬 출력에 적용(IR Update = 새 명령 발효)

Shift는 양끝 비트가 깎인다: Capture→Shift 진입 시 첫 비트가 이미 TDO쪽에 정렬되므로, N비트 레지스터를 완전히 갱신하려면 Shift에서 정확히 N번 TCK를 인가합니다(마지막 비트 시프트와 동시에 TMS=1로 Exit1).

흔한 실수: "Update 안 거치고 Exit1→RTI로 빠지면 되겠지" ❌ → Update를 안 거치면 섀도 레지스터가 출력에 적용되지 않습니다. 명령/데이터를 시프트만 하고 Update를 빠뜨리면 아무 일도 안 일어납니다.

★ 면접 핵심 ★

명령(Instruction) — 인코딩을 정확히

IR에 시프트하는 opcode가 어떤 DR을 TDI↔TDO에 연결할지 결정합니다. 1149.1 필수 명령과 인코딩 규칙:

명령선택 DR인코딩동작
BYPASSBypass(1-bit)전부 1 (all-ones) 필수1비트 우회 레지스터만 체인에 — 해당 TAP 건너뛰기
IDCODEIDCODE(32-bit)구현 정의(리셋 후 기본)32비트 칩 ID 읽기. LSB=1로 BYPASS와 구분
SAMPLE/
PRELOAD		Boundary Scan구현 정의핀 값 샘플(정상동작 방해 없이) + 출력셀 프리로드
EXTESTBoundary Scan구현 정의(흔히 all-zeros)boundary cell이 실제 핀을 구동 — 외부 배선/연결 테스트
INTESTBoundary Scan구현 정의boundary cell로 내부 로직에 자극 인가(내부 테스트)

왜 BYPASS=all-ones인가: 1149.1은 BYPASS를 "모든 1"로 강제합니다. 연결 끊김/플로팅(풀업)으로 IR이 전부 1이 되어도 안전하게 BYPASS로 떨어지도록 한 fail-safe입니다. 또 IR Capture의 LSB는 반드시 1로 규정돼 정렬 무결성을 검증합니다.

흔한 오답: "리셋하면 BYPASS가 걸린다" ❌ → Test-Logic-Reset 후 기본 명령은 IDCODE(IDCODE 미구현 시에만 BYPASS). 그래서 체인에 클럭만 줘도 ID가 먼저 나옵니다.

데이터 폭 계산

BYPASS 길이 · 체인 정렬 — 비트를 센다

여러 칩이 직렬로 묶인 체인에서 한 칩만 보려면, 나머지를 BYPASS(각 1비트)로 두고 비트를 정확히 셉니다.

예: 4-TAP 체인, 3번 칩의 32비트 IDCODE를 읽기. 3번만 IDCODE, 나머지 3개는 BYPASS. DR 체인 길이 = 1 + 1 + 32 + 1 = 35 bit. TDI 쪽 BYPASS 비트들이 먼저 통과하므로 오프셋만큼 더 시프트해야 IDCODE가 TDO로 나옵니다.

// 체인 정렬: TDI → TAP0 → TAP1 → TAP2 → TAP3 → TDO
// 목표: TAP2(IDCODE), 나머지 BYPASS
IR 시프트: BYPASS|IDCODE|BYPASS|BYPASS  // 칩별 IR 폭만큼
DR 체인 = [byp][byp][ IDCODE 32b ][byp]
        =   1  +  1  +    32     +  1   = 35 bit
// TAP3가 TDO에 가장 가까움 → 마지막에 시프트되어 나옴
각 TAP의 IR 폭은 서로 다를 수 있어 BSDL 파일에서 INSTRUCTION_LENGTH를 확인

현장 함정: BYPASS 레지스터는 정확히 1비트지만, 캡처 시 0으로 로드됩니다. 비트 카운트를 한 칸이라도 틀리면 전체 체인이 어긋나(misalignment) IDCODE가 깨져 보입니다 — "ID가 0xFFFF…"면 보통 플로팅 TDI나 정렬 오류입니다.

boundary scan 셀

BSR · BSC — EXTEST가 핀을 흔드는 원리

모든 I/O 핀마다 boundary scan cell(BSC)이 끼워져 있고, 이들이 직렬로 이어진 게 Boundary Scan Register(BSR)입니다. 각 셀은 캡처 플롭 + Update 래치 + 모드 mux 구조.

// boundary scan cell (BC_1 류) 개념 구조
always_ff @(posedge tck) if(shift) cap <= scan_in;   // 직렬 시프트
                  else if(capture) cap <= pin_or_core;     // 병렬 캡처
always_ff @(posedge tck) if(update) upd <= cap;      // Update-DR에서 래치
assign data_out = mode ? upd : core_signal;   // EXTEST=mode1 → upd가 핀 구동
assign scan_out = cap;                          // 다음 셀로 직렬 전달
mode=1(EXTEST): 코어를 끊고 Update 값이 핀을 구동 / mode=0(정상): 코어 신호가 핀으로

SAMPLE: mode=0 유지하며 정상 동작 중 핀/코어 값을 캡처(스냅샷). EXTEST: mode=1로 바꿔 PRELOAD해둔 값으로 실제 핀을 구동, 옆 칩의 입력 BSC가 그 값을 캡처 → 두 칩 사이 PCB 배선 단선/단락을 잡는다.

왜 SAMPLE/PRELOAD가 짝인가: EXTEST로 들어가기 전에 Update 래치를 안전한 값으로 채워두지 않으면, EXTEST 진입 순간 핀이 쓰레기 값을 구동합니다. PRELOAD가 그 "초기 안전값"을 먼저 적재합니다.

파형으로 보기

Shift-DR에서 1비트/클럭 — TDO는 하강엣지

읽는 법: Shift-DR 동안 TMS=0을 유지하며 매 TCK 상승엣지에 TDI를 샘플해 한 비트씩 밀어넣고, 하강엣지에 TDO로 반대편 비트를 내보냅니다(엣지 분리로 race 회피). 마지막 비트와 동시에 TMS=1을 주어 Exit1-DR로 나갑니다.
iJTAG — IEEE 1687

SIB — 네트워크를 재구성하는 비트

칩 안 수백 개의 embedded instrument(BIST·온도센서·eFuse·트레이스)를 다 고정 길이 체인에 묶으면 너무 깁니다. 1687은 SIB(Segment Insertion Bit)로 필요한 세그먼트만 체인에 끼웠다 뺐다 합니다.

// SIB = 1비트 게이트. 값에 따라 하위 세그먼트를 체인에 삽입
SIB=0 :  scan_in ─────────────► scan_out   // 닫힘: 1비트만(우회)
SIB=1 :  scan_in ─► [instrument seg] ─► scan_out  // 열림: 세그먼트 삽입

// 계층적: SIB 안에 또 SIB → 트리 형태로 동적 확장
Network = SIB_temp(0) · SIB_mbist(1 → [BIST_ctrl 8b]) · SIB_efuse(0)
SIB를 0/1로 시프트하면 다음 패스부터 체인 길이/구성이 바뀜 → "retargeting"

retargeting: 상위 추상 명령("BIST 시작")을 현재 네트워크 구성에 맞는 실제 TDI/TDO 비트열로 자동 변환. SIB가 열렸는지에 따라 비트 위치가 달라지므로 툴이 매번 다시 계산합니다.

왜 1149.1 위에 얹나: 1687은 새 핀을 안 늘립니다. 기존 TAP의 사용자정의 명령(예 GATEWAY)으로 1687 네트워크에 진입한 뒤, 그 안에서 SIB로 동적 구성. 즉 물리 인터페이스는 그대로, 접근만 똑똑해진 것.

iJTAG 기술 언어

ICL · PDL — 무엇이 있고, 어떻게 접근하나

🗺️ ICL (구조)

Instrument Connectivity Language. 네트워크의 정적 구조를 기술 — 어떤 SIB/ScanReg/instrument가 어떻게 연결됐는지. "지도(map)"에 해당.

  • 레지스터 폭, 계층, SIB 위치
  • retargeting 툴의 입력(네트워크 모델)

📜 PDL (절차)

Procedural Description Language. instrument를 어떻게 동작시키는지 절차로 기술 — "이 레지스터에 값 쓰고, 클럭 N번, 결과 읽어라". "사용설명서"에 해당.

  • iWrite/iRead/iApply/iRunLoop 등
  • ICL 위에서 동작 → 물리 비트열로 retarget
# PDL 예: MBIST instrument 기동 후 결과 확인 (개념 표현)
iWrite  mbist.MODE     0b01      # 모드 레지스터 설정
iWrite  mbist.START    1
iApply                          # 여기서 ICL을 보고 실제 TDI 비트열로 retarget → TAP에 시프트
iRunLoop 2000 tck                # BIST 수행 동안 TCK 인가
iRead   mbist.DONE     1
iRead   mbist.FAIL     0          # 기대값 비교(fail이면 mismatch)

핵심: 엔지니어는 mbist.START=1처럼 이름으로 쓰고, 툴이 ICL을 참조해 현재 SIB 구성에 맞는 비트 위치로 변환합니다. 네트워크가 바뀌어도 PDL은 그대로 — 이게 1687의 이식성입니다.

★ 면접 핵심 ★ — CoreSight DAP

JTAG2APB / DAP — DR이 버스 마스터가 된다

디버거가 칩 메모리/레지스터를 읽고 쓰려면 직렬 스캔만으론 부족합니다. DAP(Debug Access Port)는 TAP의 DR 시프트를 온칩 APB(또는 AHB/AXI) 트랜잭션으로 변환하는 다리입니다.

경로: 디버거 → (JTAG/SWD) → DP → (DPACC/APACC 레지스터) → AP(MEM-AP) → APB/AHB → 시스템 버스. JTAG에선 TAP 명령으로 DPACC/APACC DR을 선택해 35비트(예) 패킷을 시프트하면, DP가 이를 디코드해 AP 레지스터에 R/W합니다.
DAP 트랜잭션 디테일

DPACC · APACC — 한 트랜잭션의 해부

레지스터역할
DPACCDP 레지스터 접근(IR 명령). CTRL/STAT, SELECT(어느 AP·어느 뱅크) 등 설정
APACCAP 레지스터 접근(IR 명령). MEM-AP의 CSW/TAR/DRW를 R/W
CSWControl/Status Word — 전송 크기(8/16/32b), 자동증가(addr inc) 설정
TARTransfer Address Register — 접근할 시스템 주소
DRWData Read/Write — TAR 주소의 데이터. 여기 쓰면 버스에 write, 읽으면 read
// 0x2000_0000 번지에 32비트 write (개념 시퀀스)
IR=DPACC; DR← SELECT = {APSEL, APBANK}      // MEM-AP 선택
IR=APACC; DR← CSW    = SIZE_32 | ADDRINC     // 32비트, 자동증가
IR=APACC; DR← TAR    = 0x2000_0000           // 주소
IR=APACC; DR← DRW    = 0xDEAD_BEEF            // → 여기서 APB write 발생!
// 각 DR 시프트는 [RnW:1][A:2][DATA:32] 형태 (=35비트) + ACK 응답

파이프라인: AP 읽기는 한 박자 늦게(posted) 나옵니다 — 이번 트랜잭션의 ACK/데이터는 직전 요청의 결과. 그래서 마지막 값을 얻으려면 RDBUFF(DP)를 한 번 더 읽습니다. ACK 필드의 WAIT는 재시도, FAULT는 에러 처리.

흔한 오답: "AP 읽으면 즉시 그 주소 데이터가 나온다" ❌ → posted read라 한 트랜잭션 지연이 있습니다. 이를 모르면 항상 한 칸씩 어긋난 값을 읽습니다.

SWD — JTAG 대안

2핀 SWD vs 4핀 JTAG — 같은 DP, 다른 물리층

🔌 JTAG (JTAG-DP)

  • 4핀: TCK/TMS/TDI/TDO(+TRST)
  • TAP FSM 경유, 멀티드롭 데이지체인 가능
  • boundary scan(1149.1)과 공존

🪡 SWD (SW-DP)

  • 2핀: SWCLK + 양방향 SWDIO
  • Arm 전용, 같은 DP/AP 모델을 그대로 사용
  • 핀 절약(MCU에 유리), 패킷에 parity·ACK 내장

핵심: SWD는 물리 전송층만 교체한 것 — 위의 DPACC/APACC/CSW/TAR/DRW 추상은 동일합니다. SWJ-DP는 둘을 한 칩에 담아 특수 시퀀스로 JTAG↔SWD 전환합니다. 그래서 "SWD 배우면 DAP 모델은 그대로"입니다.

오해 주의: SWD가 "JTAG의 상위호환"은 아닙니다. SWD는 boundary scan을 못 합니다(1149.1 체인 접근 불가). 핀 토글 테스트가 필요하면 여전히 JTAG가 있어야 합니다.

검증 엔지니어의 시선

TAP·DAP를 어떻게 검증하나

🧩 무엇으로

  • JTAG VIP(또는 UVM agent)로 TMS 시퀀스 생성 → 16-상태 FSM 구동
  • SVA로 FSM 합법성: TMS=1×5 → TLR, Update 없이는 적용 안 됨
  • BSDL 파일 대조: IR 길이·IDCODE·셀 순서 자동 비교
  • DAP는 APB/AHB 버스 VIP로 발생 트랜잭션 체크

🎯 무엇을(코너)

  • IDCODE=리셋 기본 · BYPASS=all-ones 단언
  • IR Capture LSB=1, 모든 명령 opcode 커버리지
  • 멀티-TAP 체인 비트 정렬, BYPASS 길이=1
  • DPACC/APACC posted-read 1박자 지연, WAIT/FAULT ACK
  • 1687: SIB 0/1 모든 조합, retargeting 비트열 일치
// 어떤 상태에서든 TMS=1을 5번이면 Test-Logic-Reset 진입
ap_tlr: assert property (@(posedge tck)
   (tms [*5]) |=> (tap_state == TEST_LOGIC_RESET) );
// BYPASS 선택 시 DR 체인 기여 길이는 정확히 1비트여야 한다
ap_byp: assert property (@(posedge tck)
   (ir == BYPASS) |-> (dr_len == 1) );

TAP 상태머신은 몇 상태고, Test-Logic-Reset에 확실히 들어가려면?
총 16 상태입니다 — Test-Logic-Reset, Run-Test/Idle과, 구조가 동일한 DR열·IR열 각각 7개(Select·Capture·Shift·Exit1·Pause·Exit2·Update). TRST 없이도 TMS=1을 5 TCK 연속 인가하면 어느 상태에서든 Test-Logic-Reset로 들어가도록 FSM이 설계돼 있어, TRST는 1149.1에서 옵션 핀입니다.
BYPASS와 IDCODE의 인코딩·리셋 후 기본은?
BYPASS는 IR이 전부 1(all-ones)로 강제됩니다 — 연결 끊김으로 IR이 1이 돼도 안전하게 1비트 우회로 떨어지게 한 fail-safe입니다. IDCODE는 32비트 ID를 읽으며 LSB=1로 BYPASS와 구분됩니다. 리셋(Test-Logic-Reset) 후 기본 명령은 IDCODE(미구현 시에만 BYPASS)라, 체인에 클럭만 줘도 ID가 먼저 나옵니다.
1687 SIB가 무엇이고, JTAG2APB/DAP는 어떻게 동작하나요?
SIB(Segment Insertion Bit)는 1비트 게이트로, 시프트한 값에 따라 하위 instrument 세그먼트를 스캔체인에 끼웠다 뺐다 해 네트워크를 동적 재구성합니다. PDL의 추상 명령을 ICL 모델로 retargeting해 실제 비트열로 변환하죠. DAP는 TAP의 DR 시프트를 온칩 버스 트랜잭션으로 바꿉니다 — DPACC로 DP를, APACC로 MEM-AP의 CSW/TAR/DRW를 설정하면 AP가 APB/AHB 마스터로서 메모리를 R/W합니다. AP 읽기는 posted라 한 박자 지연이 있습니다. SWD는 같은 DP/AP 모델을 2핀으로 쓰는 대안입니다.
핵심 요약

JTAG/iJTAG 정밀 — 한 손에

  • 신호: TCK/TMS/TDI/TDO(+옵션 TRST). TDI 상승엣지 샘플, TDO 하강엣지 출력
  • 16-상태 TAP: TLR·RTI + DR/IR 7열(Select·Capture·Shift·Exit1·Pause·Exit2·Update). TMS=1×5 → TLR
  • 명령: BYPASS=all-ones, IDCODE(리셋 기본), SAMPLE/PRELOAD, EXTEST(핀 구동), INTEST
  • boundary scan: BSC(capture+update+mode) 직렬 = BSR, EXTEST로 PCB 배선 테스트
  • 1687: SIB로 동적 재구성, ICL(구조)/PDL(절차), retargeting
  • DAP: DP→AP(MEM-AP), DPACC/APACC·CSW/TAR/DRW, posted read. SWD는 2핀 대안

"JTAG은 TMS로 16-상태 TAP를 움직여 IR로 명령을, DR로 데이터를 시프트합니다. BYPASS=all-ones·IDCODE 기본 같은 인코딩 규칙, 1687 SIB의 동적 네트워크, DAP의 DPACC/APACC 트랜잭션까지 답하면 '다뤄본 사람'입니다. 검증은 JTAG VIP+SVA로 FSM·체인·DAP 규칙을 단언합니다."
