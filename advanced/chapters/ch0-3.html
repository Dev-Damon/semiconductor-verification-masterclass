전체 그림

CDV 루프 — 측정이 자극을 이끈다

Coverage-Driven Verification은 "랜덤 자극 → 커버리지 측정 → 구멍 분석 → 제약/시드 조정"을 회귀로 반복해 목표 커버리지에 수렴시키는 폐루프입니다.

핵심은 피드백입니다. 커버리지 구멍이 다음 회귀의 제약(constraint)·시드를 바꾸고, 그게 다시 자극을 만듭니다. "그냥 오래 돌리기"가 아니라 측정 기반으로 닫는 게 CDV.
기능 커버리지 문법

covergroup · coverpoint · bins

class txn; rand bit [1:0] burst; rand bit [2:0] size; rand bit [7:0] len; endclass

covergroup cg_axi(ref txn t) @(posedge clk);   // 샘플 트리거
  cp_burst : coverpoint t.burst {
    bins fixed = {2'b00};
    bins incr  = {2'b01};
    bins wrap  = {2'b10};
    illegal_bins rsvd = {2'b11};         // 맞으면 즉시 에러
  }
  cp_size : coverpoint t.size {
    bins sz[] = {[0:7]};                    // 8개 자동 분할(0..7)
  }
  cp_len  : coverpoint t.len {
    bins single = {0};
    bins mid[4] = {[1:254]};                  // 범위를 4개 bin으로 균등 분배
    bins max256 = {255};
  }
  x_bs : cross cp_burst, cp_size;             // 조합(곱) 커버리지
endgroup
샘플은 covergroup이 보는 시점(@posedge clk 또는 명시적 .sample())에 일어난다.

bins x[]는 값마다 1개씩, bins x[N]은 N개로 균등 분배, bins x = {set}은 하나의 bin. cross는 cp들의 데카르트 곱(예: 3 burst × 8 size = 24개 조합)을 본다.

두 커버리지의 차이

기능 커버리지 vs 코드 커버리지

구분기능 커버리지(functional)코드 커버리지(code)
출처사람이 vplan에서 직접 작성(covergroup)시뮬레이터가 자동 계측
측정 대상"의도한 시나리오·조합이 발생했나""RTL 코드의 구조가 실행됐나"
구멍의 의미설계 의도가 안 자극됨죽은/안 탄 코드
한계안 적으면 안 보임(작성자 의존)실행만 보고 정확성은 모름

코드 커버리지 5종: line(문장 실행), toggle(각 비트 0→1·1→0), branch(if/case 분기), condition/expression(불 조건의 각 항 참/거짓), FSM(상태·전이 도달).

둘은 상호 보완입니다. 코드 커버리지는 "TB가 RTL을 충분히 휘저었나(자극 빈약 탐지)", 기능 커버리지는 "의도한 일이 일어났나"를 봅니다. 어느 한쪽만으론 닫을 수 없습니다.

치명적 함정

100%인데 버그가 남는 두 경우

① 코드 커버리지 100% ≠ 검증 끝. 모든 line이 실행돼도 기능 커버리지 구멍(예: WRAP+narrow+back-to-back 조합)은 그대로 남는다. "line 100% 찍었으니 됐다"는 신입 단골 오답.

② all-pass ≠ 검증됨. 테스트가 전부 PASS여도 체크(scoreboard/assertion)가 없거나 약하면 단지 "안 터졌을 뿐". 커버리지가 올라가도 체크가 비어 있으면 미검증.

그래서 사인오프는 3축을 같이 봅니다: ① 기능 커버리지(의도) ② 코드 커버리지(자극 충분성) ③ 버그 발견 곡선의 수렴(더 안 나옴). 한 축만 100%는 의미가 약합니다. 특히 ②가 100%인데 ①에 구멍이 있으면 — "코드는 다 탔지만 의도는 안 자극됐다" — 가장 흔한 위험 신호.

SVA ① 두 종류

immediate vs concurrent assertion

immediate

절차 코드(always/initial) 안에서 그 시점 즉시 평가. 조합적 한 점 검사.

always @(posedge clk)
  if (wr_en)
    assert(addr < MEM_SIZE)
    else $error("OOR addr");

시간(여러 클럭)에 걸친 관계는 못 본다.

concurrent

클럭 기준으로 매 사이클 평가. property+temporal 연산자로 여러 클럭에 걸친 시퀀스를 검사.

property p_ack;
  @(posedge clk) disable iff(!rst_n)
    req |-> ##[1:3] ack;  // 1~3클럭 내 ack
endproperty
a_ack : assert property(p_ack);

대부분의 프로토콜 규칙이 여기 속한다.

혼동 주의: immediate는 "절차문, 즉시", concurrent는 "클럭 샘플링, 시간에 걸침". concurrent에서 신호는 preponed 영역(클럭 엣지 직전 안정값)으로 샘플돼 race를 피합니다. disable iff로 리셋 중엔 평가를 끕니다.

SVA ② 연산자와 cover

|-> vs |=> · cover property

표기이름의미
|->overlapping implication선행 만족 → 같은 클럭부터 후행 검사
|=>non-overlapping선행 만족 → 다음 클럭부터 후행 검사(= |-> ##1)
##Ndelay정확히 N클럭 뒤
##[m:n]range delaym~n클럭 사이
s[*3]consecutive repeats가 3클럭 연속
$rose/$felledge이전→현재 0→1 / 1→0 전이
// 버그 잡기(assert)가 아니라
// "이 시퀀스가 일어났나"를 측정(cover)
c_btb : cover property(@(posedge clk)
  $rose(start) ##[1:2] done ##1 $rose(start));
// → back-to-back 트랜잭션 커버 항목

assert property는 위반 시 fail(버그 검출), cover property는 도달 시 hit(커버리지 측정). 같은 SVA 문법으로 체커와 커버 항목을 둘 다 만든다 — 이게 ABV의 핵심.

랜덤·시드·회귀

constrained-random → seed → regression

🎲 seed

같은 TB라도 seed가 바뀌면 다른 랜덤 시퀀스. seed는 결과를 재현하는 키 — fail seed를 저장해야 디버그 가능.

📦 regression

수백~수천 seed를 병렬로 야간 실행(LSF/grid). 각 run의 커버리지 DB를 모은다.

🔗 merge

모든 run의 커버리지를 합산(merge)해 누적 진행도를 본다. 한 run만으론 못 닫는다.

# 여러 seed로 회귀 → 커버리지 누적 병합 (벤더 예: VCS urg)
for s in 1 2 3 ... 500; do simv +ntb_random_seed=$s -cm line+cond+fsm+tgl; done
urg -dir simv.vdb/*  # merge → 통합 커버리지 리포트(HTML)

seed 1개로 100%는 우연일 수 있고, 디버그하려면 실패 seed를 반드시 로깅해야 한다. seed 없이 "랜덤이라 재현 안 됨"은 검증 실격.

언제 닫나

Coverage Closure — 사인오프 기준

Coverage closure = vplan의 모든 커버 항목이 채워지고(목표 도달), 남은 구멍은 분석을 거쳐 의도적으로 제외(waiver/exclusion)되어 더 채울 게 없는 상태. "100% 그 자체"가 아니라 "설명되지 않은 구멍이 0"이 본질.

사인오프 체크리스트(실무 통상):

  • 기능 커버리지 = 100% (모든 bin·cross hit 또는 waiver)
  • 코드 커버리지 ≈ 95~100%, 미달분은 분석/제외 사유 명시(unreachable·dead code)
  • 모든 assertion fail 0, 회귀 pass
  • 버그 발견 곡선이 수렴(시간 대비 신규 버그 ≈ 0)
랜덤이 안 닿는 곳

Formal Verification — FPV는 어디에 쓰나

Formal은 자극을 던지지 않습니다. 수학적 증명(model checking)으로 "이 property가 모든 입력·모든 상태에서 참인가"를 탐색합니다. 반례가 있으면 최단 counterexample 파형을 줍니다.

✅ 잘 맞는 곳

  • 제어 로직: arbiter 기아·데드락 free
  • FIFO over/underflow 불가 증명
  • 프로토콜 준수(AXI 등) FPV
  • CDC·레지스터맵·X-propagation
  • 코너 커버 구멍의 도달성 증명/반증

⚠️ 한계

  • 상태 폭발 — 큰 데이터패스엔 부적합
  • 증명엔 assume(제약)이 필요(과제약 위험)
  • 곱셈기·대형 메모리 full proof는 어려움
  • 그래서 보통 bounded proof로 절충

시뮬 vs formal: 시뮬은 "본 시나리오만" 검증(예시 기반), formal은 "본 적 없어도 전부" 증명(전수). 둘은 경쟁이 아니라 분담 — 제어부는 formal, 데이터패스·시스템 시나리오는 시뮬/CDV로.

검증 엔지니어의 시선

UVM에서 이 모든 게 어디 붙나

🧱 어디에

  • covergroup은 보통 monitor가 본 트랜잭션에서 cg.sample()
  • scoreboard가 정답 비교(체크), 빈 체크면 미검증
  • SVA는 interface/bind로 RTL에 항상 켜둠(protocol checker)
  • sequence/constraint가 자극을 만들고, 커버리지 피드백으로 reactive하게 조정

🎯 closure 운영

  • 야간 회귀 → 커버리지 merge → 구멍 리스트
  • 구멍을 vplan 항목에 역매핑(traceability)
  • 못 닿는 코너는 directed test 또는 formal로 보강
  • 설명 가능한 미달은 waiver 문서화 후 사인오프

bind로 SVA를 RTL에 주입하면 RTL을 수정하지 않고도 protocol checker를 항상 켤 수 있습니다. "기능은 도는데 규칙 위반"을 회귀 내내 잡아내는 게 핵심.

면접 심화 질문

여기까지 답하면 "실무자"로 보인다

기능 커버리지와 코드 커버리지의 차이, 둘 다 100%면 끝인가요?
코드 커버리지는 시뮬레이터가 자동 계측(line/toggle/branch/condition/FSM)해 "RTL 구조가 실행됐나"를, 기능 커버리지는 사람이 vplan으로 작성한 covergroup으로 "의도한 시나리오·조합이 일어났나"를 봅니다. 코드 100%여도 기능 구멍은 남고, 둘 다 100%여도 체크(scoreboard/assertion)가 약하면 미검증입니다. 그래서 버그 발견 곡선 수렴까지 함께 봅니다.
concurrent assertion은 어떻게 동작하나요? immediate와 차이는?
concurrent는 클럭 기준으로 매 사이클 평가하고, 신호를 preponed 영역(엣지 직전 안정값)으로 샘플해 race를 피하며 |->/|=>/##/[*] 같은 temporal 연산자로 여러 클럭 시퀀스를 검사합니다. immediate는 always/initial 절차문 안에서 그 시점 즉시 한 점만 평가합니다. 또 disable iff로 리셋 중 평가를 끕니다.
coverage closure란 무엇이고 formal은 어디에 씁니까?
closure는 vplan의 모든 커버 항목이 목표에 도달하고 남은 구멍은 분석 후 의도적으로 제외(waiver)되어 "설명되지 않은 구멍이 0"인 상태입니다. 단순 100%가 아니라 추적 가능성이 핵심이죠. formal은 자극 없이 모든 입력·상태에서 property를 증명하는 기법으로, arbiter 데드락/기아, FIFO over·underflow, 프로토콜 준수, 도달성 같은 제어·코너에 강하고, 상태 폭발 때문에 큰 데이터패스엔 bounded proof로 절충합니다.
핵심 요약

CDV·커버리지·SVA — 한 손에

  • CDV = 랜덤 → 측정 → 구멍분석 → 제약/시드 폐루프
  • 기능 커버리지(사람·의도) vs 코드 커버리지(자동 line/toggle/branch/cond/FSM)
  • SVA: immediate(절차·즉시) vs concurrent(클럭·시퀀스), cover property로 측정
  • seed·regression·merge로 커버리지 누적
  • closure = "설명되지 않은 구멍 0" + 버그곡선 수렴
  • formal = 전수 증명(제어·코너), 시뮬은 예시 기반

"커버리지는 진행도를 측정하고, assertion은 규칙을 감시하고, formal은 코너를 증명합니다. CDV는 이 셋을 폐루프로 돌려 '설명되지 않은 구멍 0'에서 사인오프합니다."
