AXI 프로토콜, 신호 레벨까지

개념판에서 "5채널·핸드셰이크·버스트"를 잡았다면, 이제 면접관이 파고드는 곳 — 정확한 핸드셰이크 규칙, AxLEN/AxSIZE 인코딩, WRAP 계산, WSTRB, 순서 규칙까지 내려갑니다.

이 챕터의 목표

"안다"에서 "신호로 설명한다"로

✅ 개념판에서 한 것

  • 읽기/쓰기 분리, 5채널의 존재
  • VALID/READY가 핸드셰이크라는 것
  • 버스트로 대역폭을 올린다는 직관

🎯 심화판에서 더할 것

  • 핸드셰이크 의존성 규칙(데드락 방지)
  • AxLEN/AxSIZE/AxBURST 비트 인코딩
  • WRAP 경계 계산, WSTRB, xRESP
  • ID 기반 순서·outstanding·OOO

기준 스펙: ARM IHI 0022 (AMBA AXI Protocol Specification). 면접에서 "AXI 좀 봤다"는 사람과 "AXI 다뤄봤다"는 사람을 가르는 건 이 디테일들입니다.

전체 신호 지도

5개 채널과 핵심 신호

채널방향핵심 신호역할
AWM→SAWADDR, AWLEN, AWSIZE, AWBURST, AWID, AWVALID/READY쓰기 주소·속성
WM→SWDATA, WSTRB, WLAST, WVALID/READY쓰기 데이터(beat들)
BS→MBRESP, BID, BVALID/READY쓰기 응답(1개)
ARM→SARADDR, ARLEN, ARSIZE, ARBURST, ARID, ARVALID/READY읽기 주소·속성
RS→MRDATA, RRESP, RLAST, RID, RVALID/READY읽기 데이터(beat들)
M=Master(요청측), S=Slave(응답측). 5채널은 서로 독립이라 각자의 속도로 흐릅니다.

AXI4에는 WID가 없습니다. (AXI3의 쓰기 데이터 인터리빙이 AXI4에서 제거됨) — 면접 함정 단골.

핵심 중의 핵심

VALID / READY 핸드셰이크 4규칙

모든 채널이 똑같은 규칙을 씁니다: VALID와 READY가 같은 클럭 상승엣지에 모두 1이면 그 박자에 전송 성립.

  • R1. 소스는 READY를 기다리지 않고 VALID를 띄울 수 있어야 한다 — VALID가 READY에 의존하면 안 됨(데드락).
  • R2. 목적지는 VALID를 보고 나서 READY를 줘도 된다(기다려도 됨).
  • R3. 한번 VALID를 띄우면 핸드셰이크가 일어날 때까지 내리면 안 된다.
  • R4. VALID 유지 동안 payload(주소/데이터)는 안정적이어야 한다.
버스트 인코딩 ①

AxLEN · AxSIZE — 숫자를 정확히

AxLEN — 전송 개수

beats = AxLEN + 1. 즉 AxLEN=0이면 1 beat, AxLEN=3이면 4 beats.

  • AXI4: INCR는 최대 256 beats (LEN 0–255)
  • WRAP/FIXED 및 AXI3: 최대 16 beats

AxSIZE — beat당 바이트

bytes/beat = 2^AxSIZE.

AxSIZE바이트
0 / 1 / 21 / 2 / 4 B
3 / 48 / 16 B
5 / 6 / 732 / 64 / 128 B

데이터 버스 폭을 넘을 수 없음.

가장 흔한 오답: "AxSIZE=4면 4바이트" ❌ → 실제론 2^4=16바이트. "AxLEN=4면 4 beats" ❌ → 실제론 5 beats. 이 둘을 정확히 말하면 점수를 땁니다.

버스트 인코딩 ②

AxBURST · WRAP 경계 계산

AxBURST타입주소 진행용도
0b00FIXED주소 고정(같은 곳 반복)FIFO 같은 주변장치
0b01INCRbeat마다 +size일반 메모리 접근
0b10WRAP경계서 시작점으로 되감김캐시 라인 채우기
0b11reserved——

WRAP 규칙: 길이는 2·4·8·16 중 하나여야 하고, 경계 = (beat당 바이트) × (beat 수). 예) 4 beats × 4B = 16B 경계. 시작 주소 0x108이면 → 108 → 10C → 100 → 104 (16B 블록 0x100~0x10F 안에서 되감김). critical-word-first로 CPU가 원하는 워드를 먼저 받는 게 핵심.

부분 쓰기의 비밀

WSTRB — 바이트 레인 마스크

WSTRB는 데이터 버스의 바이트 1개당 1비트입니다(64-bit 버스 → 8비트). 그 박자에 어느 바이트가 유효한지를 알려줍니다.

  • 비정렬(unaligned)·부분 쓰기·좁은 전송(narrow)에서 필수
  • WSTRB[n]=1 → WDATA의 n번째 바이트를 메모리에 씀
  • 읽기에는 strobe가 없음(전체 RDATA 중 유효 바이트는 주소/size로 판단)
// 64-bit 버스, 주소 0x..2 에 2바이트만 쓰기
WDATA  = 0x____BBAA____  // byte2,3 유효
WSTRB  = 8'b0000_1100    // lane 2,3 만 1
// → 메모리의 해당 2바이트만 갱신

WSTRB를 빼먹고 전체를 쓰면 인접 바이트를 덮어써 데이터 오염 버그. 검증에서 자주 잡는 코너.

순서와 동시성

ID · Outstanding · Out-of-Order

🏷️ ID

AxID/BID/RID. 같은 ID의 트랜잭션은 순서 보존, 다른 ID는 순서 뒤바뀜 허용.

📚 Outstanding

응답을 기다리지 않고 주소를 여러 개 미리 발사. 메모리 지연을 감춰 대역폭↑.

🔀 Out-of-Order

느린 슬레이브의 응답을 나중에, 빠른 건 먼저. ID로 짝을 맞춤.

WLAST / RLAST: 버스트의 마지막 beat에 1. 슬레이브/마스터가 버스트 끝을 아는 신호. 쓰기 응답 B는 WLAST 핸드셰이크 이후에만 나온다.

쓰기 데이터(W)는 항상 순서대로 보내야 함(AXI4엔 WID 없음). 읽기 데이터는 같은 ID 안에선 순서 보존.

응답 코드

BRESP / RRESP — 2비트로 말하는 결과

코드이름의미
0b00OKAY정상 완료
0b01EXOKAY배타적 접근(exclusive) 성공 — 락/세마포어용
0b10SLVERR슬레이브가 에러 반환(접근은 도달, 동작 실패)
0b11DECERR디코드 에러 — 존재하지 않는 주소(interconnect가 반환)

SLVERR vs DECERR가 면접 단골: SLVERR은 "목적지엔 닿았는데 그쪽이 거부", DECERR은 "그 주소를 가진 슬레이브가 아예 없음(주소맵 구멍)". 검증에서 둘을 구분해 자극·체크합니다.

한 장으로 보는 읽기 버스트

Read 트랜잭션 타이밍 (4 beats)

AR에서 주소 1번 수락 → R 채널로 D0~D3 네 박자가 흐르고, 마지막 beat에 RLAST=1. RREADY가 0인 동안은 받는 쪽이 아직 준비되지 않았다는 뜻이라 슬레이브가 데이터를 멈추고 기다립니다.
검증 엔지니어의 시선

AXI를 어떻게 검증하나

🧩 무엇으로

  • AXI VIP(Verification IP) — 상용 마스터/슬레이브 BFM
  • UVM agent로 트랜잭션 자극·관찰
  • 프로토콜 assertion(ARM/벤더 제공 SVA)로 규칙 위반 즉시 검출

🎯 무엇을(커버리지 코너)

  • 모든 버스트 타입×길이×size 조합
  • 비정렬·narrow·부분 WSTRB
  • 최대 outstanding, OOO 응답, 같은/다른 ID
  • SLVERR/DECERR/EXOKAY 응답 경로
  • 받는 쪽이 READY를 한참 늦게 주는 극단 상황

"기능은 도는데 프로토콜을 어긴" 경우가 제일 위험합니다. 그래서 protocol checker(assertion)를 항상 켜두고 회귀를 돌립니다.

면접 심화 질문

여기까지 답하면 "실무자"로 보인다

VALID가 READY를 기다리면 왜 안 되나요?
서로가 서로를 기다리는 데드락이 생길 수 있기 때문입니다. 스펙상 소스는 READY와 무관하게 VALID를 띄울 수 있어야 하고, 목적지는 VALID를 보고 READY를 줘도 됩니다. 즉 의존은 한 방향(READY→VALID 금지)만 허용됩니다.
AWLEN=7, AWSIZE=3이면 총 몇 바이트 전송인가요?
beats = 7+1 = 8, beat당 = 2³ = 8바이트 → 총 64바이트입니다.
SLVERR와 DECERR 차이는?
DECERR은 주소를 디코드할 슬레이브가 없을 때 interconnect가 반환하고, SLVERR은 슬레이브엔 도달했지만 그쪽에서 에러를 반환한 경우입니다.
핵심 요약

AXI 정밀 — 한 손에

  • 핸드셰이크: VALID는 READY에 의존 금지, VALID는 핸드셰이크까지 유지
  • beats=AxLEN+1, bytes/beat=2^AxSIZE
  • BURST: FIXED/INCR/WRAP(2·4·8·16, 캐시라인)
  • WSTRB=바이트 레인 마스크, xLAST=버스트 끝
  • 같은 ID 순서보존·다른 ID OOO·outstanding
  • 응답: OKAY/EXOKAY/SLVERR/DECERR

"AXI는 5개 독립 채널을 VALID/READY로 묶고, ID·버스트·WSTRB로 고대역·아웃오브오더를 만든 프로토콜입니다. 검증은 프로토콜 assertion과 코너 커버리지로 합니다."
