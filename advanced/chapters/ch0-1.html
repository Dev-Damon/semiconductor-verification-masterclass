RTL에서 실리콘까지, 흐름의 진짜 이름

개념판에서 "설계→검증→제조"의 큰 그림을 잡았다면, 이제 면접관이 파고드는 곳 — 합성·DFT·P&R·STA·테이프아웃이라는 실제 단계와 툴 이름, PPA 트레이드오프, 검증이 왜 절반인지까지 내려갑니다.

이 챕터의 목표

"흐름을 안다"에서 "단계와 툴로 말한다"로

✅ 개념판에서 한 것

  • 설계→제조→테스트의 큰 흐름
  • SoC = 여러 IP를 한 칩에 통합
  • "검증이 중요하다"는 직관

🎯 심화판에서 더할 것

  • EDA 흐름의 실제 단계와 툴명(합성·P&R·STA)
  • 추상화 사다리(behavioral→RTL→gate→transistor, TLM)
  • PPA 트레이드오프, 사인오프의 의미
  • 검증 계층(IP→SoC→post-silicon)과 shift-left

기준 흐름: RTL-to-GDSII(디지털 ASIC) 표준 EDA 플로우. 면접에서 "칩 어떻게 만드냐"에 "설계하고 공장 보낸다"가 아니라 합성→DFT→P&R→STA 사인오프→테이프아웃이라고 단계 이름으로 답하면 레벨이 달라집니다.

전체 지도

EDA 흐름 — 툴 이름까지

왼쪽 4단계(합성·DFT·P&R·STA)가 EDA 툴이 도는 자동화 흐름. STA를 통과(사인오프)해야 GDSII를 만들어 Fab으로 넘기고, 실리콘이 돌아오면 post-silicon bring-up이 시작됩니다.

지도를 줌인하는 것과 비슷합니다 — 위쪽 레벨일수록 동작의 큰 그림만 빠르게 보고, 아래로 내려갈수록 세부(게이트·트랜지스터)까지 정확히 보지만 느립니다. 합성은 RTL을 gate 네트리스트로, P&R은 gate를 물리 배치(layout)로, 제조는 그걸 transistor로 실체화합니다. 한 단계 내려갈 때마다 "정말 같은가?"를 검증해야 합니다.

front-end ①

논리 합성 — RTL을 게이트로

합성기는 RTL을 읽어 표준셀 라이브러리의 게이트로 매핑하고, 타이밍·면적·전력 제약(constraint)을 만족하도록 최적화합니다.

  • 입력: RTL + 표준셀 라이브러리(.lib) + 제약(.sdc)
  • 출력: gate-level netlist + 타이밍 리포트
  • 툴: Synopsys Design Compiler, Cadence Genus
# SDC: 클럭과 제약을 합성기에 알려준다
create_clock -name CLK -period 2.0 [get_ports clk]
# 500 MHz... 2.0 ns 주기  (period(ns) = 1000 / freq(MHz))
set_input_delay  0.4 -clock CLK [all_inputs]
set_output_delay 0.4 -clock CLK [all_outputs]
set_max_area 0   # 면적 최소화
.sdc(Synopsys Design Constraints) — 클럭·I/O 지연·면적 목표

합성이 "통과"해도 제약(.sdc)이 틀리면 의미가 없습니다. 클럭 주기를 잘못 잡으면 타이밍이 통과한 것처럼 보여도 실제 칩은 그 주파수에서 못 돕니다 — "garbage in, garbage out".

front-end ②

DFT — 만든 뒤에 "테스트할 수 있게"

DFT(Design For Test)는 제조 후 결함을 걸러내기 위한 회로를 합성 단계에 미리 삽입합니다. 칩이 "동작하는지"가 아니라 "잘 만들어졌는지"를 보는 장치입니다.

  • scan chain: 플립플롭을 시프트 레지스터로 엮어 내부 상태를 직접 넣고 빼기
  • MBIST: 메모리 자체 테스트 로직
  • JTAG / boundary scan(IEEE 1149.1): 핀 레벨 접근
  • 패턴 생성: ATPG(자동 테스트 패턴)

구분이 핵심:

  • 기능 검증 = "설계가 맞나?"(pre-silicon, 시뮬)
  • 제조 테스트 = "이 한 개의 칩에 제조 결함이 없나?"(post-silicon, ATE)

DFT는 후자를 위한 것. fault coverage(예: stuck-at 99%+)로 품질을 측정합니다.

DFT를 "검증 커버리지"와 혼동하면 함정. scan/fault coverage(제조 결함)와 functional/code coverage(설계 버그)는 완전히 다른 지표입니다.

back-end

P&R · STA — 물리와 타이밍의 진실

단계하는 일대표 툴
Floorplan블록·매크로·전원망(PG) 배치ICC2 / Innovus
Placement표준셀 배치ICC2 / Innovus
CTS클럭 트리 합성(스큐 균형)ICC2 / Innovus
Routing실제 배선(metal layer 연결)ICC2 / Innovus
STAsetup/hold 타이밍 검증PrimeTime

STA(Static Timing Analysis)는 자극(테스트벡터) 없이 모든 경로의 지연을 정적으로 계산해 타이밍을 검증합니다. 핵심 지표는 slack: slack = required_time − arrival_time. slack ≥ 0이면 통과, 음수면 위반(setup이면 더 빠른(high-drive/LVT) 셀로 교체·리타이밍으로 데이터 경로 가속, hold면 데이터 경로에 버퍼/지연셀 삽입).

P&R 후엔 실제 배선의 기생 성분(RC)을 추출(SPEF)해 STA에 넣습니다 — "배치 전 추정"이 아니라 "배선 후 실측 기반" 타이밍.
사인오프의 의미

Sign-off — "이제 공장에 보내도 된다"

사인오프는 테이프아웃 전에 통과해야 하는 최종 검증 게이트들입니다. 하나라도 깨지면 칩을 못 보냅니다.

사인오프무엇을 보장대표 툴
STA모든 코너에서 타이밍 만족(slack≥0)PrimeTime
DRC레이아웃이 공정 설계규칙 위반 없음Calibre / IC Validator
LVS레이아웃 = 회로도(netlist) 일치Calibre / IC Validator
Power(IR/EM)전압 강하·전류밀도 한계 내Voltus / RedHawk
Formal(LEC)RTL ≡ netlist 논리 등가Conformal / Formality

multi-corner / multi-mode(MCMM)가 핵심: SS/FF/TT 공정, 저온/고온, 저전압/고전압 여러 코너 전부에서 통과해야 합니다. "한 코너만 통과"는 사인오프가 아닙니다.

왜 검증이 절반인가

RTL sim 통과 ≠ silicon 동작

면접 단골 질문입니다. "시뮬레이션이 다 통과했는데 왜 검증이 끝이 아닌가?" — RTL 시뮬레이터는 이상화된 0지연·동기 세계를 가정하기 때문입니다.

  • 타이밍: 시뮬은 사이클 단위, 실제는 셀 지연·배선 RC가 존재 → STA로 별도 검증
  • CDC: 비동기 클럭 도메인 횡단 → 시뮬에선 안 보이는 메타스테이빌리티
  • async reset: 리셋 release 타이밍·복구
  • X 전파: 미초기화·unknown이 시뮬과 게이트에서 다르게 거동

대표 함정 4가지

  • 타이밍: RTL은 통과, 실제 주파수에서 setup 위반
  • X-optimism: RTL 시뮬이 if/else·case에서 X 조건을 낙관적으로 0/1로 굳혀 버그를 숨김 → 게이트 레벨 sim(X-pessimistic)이나 실리콘에서 뒤늦게 드러남
  • CDC: 동기화기 없는 횡단 → 간헐적 글리치(재현 어려움)
  • async: 리셋 복구 타이밍 위반으로 미세 결함
그래서 RTL 시뮬 외에 CDC 정적분석(SpyGlass-CDC 등)·gate-level sim(SDF 백애노테이션)·STA를 따로 돌립니다. 이 다층 검증이 프로젝트 공수의 절반 이상을 차지하는 이유입니다.

PPA 트레이드오프

Power · Performance · Area — 셋은 동시에 못 가진다

⚡ Power

동적+누설 전력. 전압↓·클럭 게이팅으로 줄이면 보통 성능이 깎임.

🚀 Performance

주파수·IPC. 주파수↑는 더 빠른(큰·전력 큰) 셀과 전압↑을 요구.

📐 Area

다이 면적=원가. 면적↓는 셀을 줄여 타이밍 여유·전력 마진을 깎음.

예시 트레이드오프: 타이밍 위반 경로를 더 빠른 셀(high-drive)로 바꾸면 → slack은 좋아지지만 면적·전력↑. Vt 선택도 마찬가지 — LVT는 빠르지만 누설↑, HVT는 느리지만 누설↓. 합성·P&R 전체가 이 세 축의 최적화 문제입니다.

자동차에서 "빠르고, 연비 좋고, 가벼운" 차를 동시에 만들 수 없는 것과 같습니다. 칩도 PPA 셋을 한꺼번에 최고로 만들 수 없으니, 무엇을 우선할지 스펙으로 먼저 정하고 그 방향으로 튜닝합니다.

마스크와 리스핀

왜 "한 번에" 맞춰야 하나 — 비용의 무게

테이프아웃은 포토마스크 세트 제작으로 이어집니다. 첨단 공정일수록 마스크 수가 많고(수십 장), 한 세트가 매우 비쌉니다(첨단 노드에서 마스크+NRE는 흔히 수백만 달러 규모).

  • 리스핀(re-spin): 버그로 다시 마스크 만들고 재제조 — 비용+수개월 일정 손실
  • full-layer vs metal-only(ECO): 금속층만 바꾸는 부분 수정으로 일부 비용을 줄이기도

검증이 프로젝트 공수의 절반 이상인 근본 이유 — 한 번 찍은 칩은 출고 후 내부 회로를 고칠 수 없고, 잘못을 바로잡으려면 리스핀이 곧 돈과 시간입니다. "사후 수정 불가"가 검증을 비싸게 만듭니다.

"버그 나면 펌웨어로 우회하면 되지" — 일부는 맞지만, 하드웨어 로직·타이밍·아날로그 결함은 SW로 못 고칩니다. 그래서 shift-left와 사인오프 게이트가 강박적으로 엄격합니다.

검증 엔지니어의 시선

이 흐름을 어떻게 검증하나

🧩 pre-silicon (왼쪽으로)

  • UVM 환경 + 제약랜덤 자극 + functional coverage
  • SVA assertion으로 프로토콜·불변식 즉시 검출
  • 한 단계 내려갈 때 LEC(formal equivalence)로 RTL≡netlist 보장
  • CDC/lint 정적분석으로 시뮬에 안 잡히는 결함
  • 속도 위해 에뮬레이션·FPGA 프로토타입으로 SoC·SW 부팅

🎯 post-silicon (오른쪽)

  • 실측 코너(전압·온도·주파수 shmoo)에서 동작 확인
  • 실리콘 디버그(스캔 덤프·trace)로 사일런트 버그 추적
  • ATE에서 제조 테스트(DFT 패턴) 적용
  • SW 브링업: 부트로더→드라이버→OS

"기능 커버리지(설계 버그) vs 패스/페일 코너(실리콘) vs fault 커버리지(제조 결함)"는 서로 다른 세 가지. 면접에서 이 셋을 구분해 말하면 검증 실무자로 보입니다.

면접 심화 질문

여기까지 답하면 "실무자"로 보인다

사인오프(sign-off)란 무엇인가요?
테이프아웃 전 통과해야 하는 최종 검증 게이트들입니다. 대표적으로 STA(타이밍, slack≥0 · PrimeTime), DRC/LVS(레이아웃 규칙·회로 일치 · Calibre), Power/IR-drop, LEC(RTL≡netlist 논리 등가)가 있고, 모든 공정·전압·온도 코너(MCMM)에서 통과해야 합니다.
PPA가 뭐고 왜 트레이드오프인가요?
Power(전력)·Performance(성능/주파수)·Area(면적)입니다. 셋은 서로 충돌해서 — 예를 들어 타이밍을 맞추려 더 빠른 셀을 쓰면 면적·전력이 늘고, 누설을 줄이려 HVT 셀을 쓰면 느려집니다. 그래서 무엇을 우선할지 스펙으로 정하고 합성·P&R에서 그 방향으로 최적화합니다.
IP 검증과 SoC 검증의 차이는?
IP 검증은 한 블록 내부 기능을 UVM·제약랜덤·커버리지로 철저히 닫는 것이고, SoC 검증은 다수 IP의 통합·버스 상호작용·SW 부팅 같은 시나리오를 봅니다. 후자는 시뮬이 느려 보통 에뮬레이션·FPGA를 씁니다. shift-left로 버그는 가능한 한 IP 단계에서 잡습니다.
post-silicon validation이 뭔가요?
실제로 돌아온 칩(실리콘)을 랩 보드·ATE에서 실측해 검증하는 단계입니다. 전압·온도·주파수 코너(shmoo)를 쓸어 동작을 확인하고, 스캔 덤프·trace로 사일런트 버그를 디버그하며, DFT 패턴으로 제조 결함을 거릅니다. 여기서 발견된 치명 버그는 리스핀(re-spin)으로 이어질 수 있어 비용이 큽니다.
핵심 요약

제작 흐름 정밀 — 한 손에

  • 흐름: RTL → 합성(DC/Genus) → DFT → P&R(ICC2/Innovus) → STA(PrimeTime) → tape-out → Fab → bring-up
  • 추상화: behavioral→TLM→RTL→gate→transistor
  • 사인오프=STA/DRC/LVS/Power/LEC, 모든 코너(MCMM)
  • PPA는 트레이드오프(빠르게=크고 전력↑)
  • 검증 계층 IP→SoC→post-silicon, shift-left
  • RTL sim 통과 ≠ silicon(타이밍·X·CDC·async)
