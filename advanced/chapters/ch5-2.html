전력의 두 갈래

Dynamic vs Leakage — 식부터 정확히

동적 전력 (스위칭)

Pdyn = α · C · V² · f

  • α = activity factor(토글 확률)
  • C = 스위칭 정전용량
  • V = 공급전압(제곱으로 들어옴)
  • f = 클럭 주파수(1차)

충전·방전 시 C·V²의 에너지가 매 토글마다 소모.

누설 전력 (정적)

Pleak = V · Ileak

  • 클럭이 멈춰도 흐름(서브스레숄드·게이트 누설)
  • 온도↑ → Ileak 급증(지수적)
  • Vt(문턱전압)↓ → 누설↑
  • V에 대해 대략 선형(∝V) 이상으로 증가

미세공정·고온일수록 비중 커짐.

흔한 오답: "전력은 주파수에 비례하니 f만 낮추면 된다" ❌ → V가 제곱으로 들어가므로 V를 낮추는 게 효과가 압도적. 그런데 V를 낮추면 게이트가 느려져 f도 못 올림 → 그래서 V와 f를 함께 움직이는 게 DVFS.

진짜 지표

energy/op — "빨리 끝내고 끄기"의 수학

전력(W)이 아니라 작업당 에너지(J/op)가 배터리를 결정합니다. 같은 일을 한다면:

E = P · t. 주파수 f를 올리면 t는 1/f로 줄지만 P는 V²f로 늘어남. 동적 에너지 자체는 Edyn ≈ α·C·V² (per op, f와 무관) — 에너지를 줄이는 핵심은 V.

race-to-idle vs 천천히: 누설이 크면 "빨리 끝내고 슬립(power gating)"이 유리, 동적이 지배적이고 누설이 작으면 "전압 낮춰 천천히"가 유리. 실제 governor는 이 트레이드오프를 부하로 판단.

개발자 직관: CPU를 100%로 0.5초 돌리고 끄기 vs 50%로 1초 끄지 않기 — 어느 쪽이 배터리에 좋은지는 누설/동적 비율에 달림. "느리게 = 항상 절약"이 아닙니다.

전압/주파수 짝의 테이블

OPP — Operating Performance Point

각 성능 단계는 (V, f) 쌍으로 정의됩니다. 이 쌍의 목록이 OPP 테이블이고, 보통 펌웨어/디바이스트리/PMIC가 들고 있습니다.

OPPf (MHz)V (mV)상대 Pdyn (∝V²f)용도
OPP03007001.0×idle / 배경
OPP18008003.5×일반 부하
OPP214009007.7×인터랙티브
OPP32000100013.6×피크 / boost
상대값은 OPP0을 1.0으로 정규화: (V/0.7)²·(f/300). f가 6.7배 늘 때 P는 ~13.6배 — V 제곱항 때문.

OPP는 임의 조합이 아니라 실리콘이 보장하는 V/f 곡선 위의 점들. "1GHz에 600mV" 같은 검증 안 된 점을 쓰면 타이밍 fail.

누가 OPP를 고르나

Linux cpufreq governor

커널의 governor가 부하를 보고 어떤 OPP로 갈지 결정하고, cpufreq driver가 클럭·PMIC를 실제로 건드립니다.

governor정책
performance항상 최고 OPP 고정
powersave항상 최저 OPP 고정
ondemand이용률 임계 넘으면 즉시 최고로(점프)
conservative이용률 따라 한 단계씩 천천히
schedutil스케줄러 이용률(PELT) 기반, 현대 기본

ondemand는 유저공간 타이머로 폴링하던 옛 방식, schedutil은 스케줄러가 직접 "이 태스크의 util이 이만큼이니 이 주파수" 하고 알려줘 반응이 빠르고 정확합니다. 최근 커널 기본값.

$ cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor → schedutil
전압을 실제로 바꾸는 길

PMIC 제어 — PMBus / I2C / SPMI

코어 전압을 만드는 건 SoC 밖의 PMIC(Power Management IC). SoC는 사이드밴드 버스로 "전압 올려/내려"를 명령합니다.

버스풀네임특징
I2C2-wire serial범용·저속, 일반 PMIC 레지스터 접근
PMBusPower Management BusI2C 기반 표준, 전압/전류/온도 텔레메트리 포함
SPMISystem Power Management InterfaceMIPI 표준, 모바일 SoC↔PMIC 저지연 2-wire
// 의사코드: OPP3(1000mV)로 전압 상향 명령
pmic_write(VOUT_REG, mv_to_code(1000));   // SPMI/I2C 트랜잭션
while (pmic_read(STATUS) & VOUT_SETTLING) ; // 안정될 때까지 폴링
// ← 여기서 'settled' 확인 전엔 주파수를 올리면 안 된다 (핵심!)

전압 상승은 즉시가 아님. 레귤레이터 slew rate(예 mV/µs)와 출력 캡 충전 시간이 있어 settling time이 존재. 이걸 안 기다리면 다음 슬라이드의 사고가 납니다.

★ 면접 핵심 ★

V/f 전환 시퀀싱 — 순서가 생명

전압과 주파수는 동시에 바꾸면 안 됩니다. 올릴 때와 내릴 때 순서가 반대입니다.

▲ 성능 올릴 때

V 먼저 ↑
→
settle 대기
→
f ↑

높은 f는 높은 V를 요구. V가 충분히 올라간 뒤에 f를 올려야 타이밍이 닫힌다.

▼ 성능 내릴 때

f 먼저 ↓
→
V ↓

낮은 V로 못 버티는 높은 f가 잠시도 없도록. f를 먼저 낮춘 뒤 V를 내린다.

한 줄 규칙: "항상 높은 V와 낮은 f의 안전한 쪽으로 먼저 간다." 즉 (V,f) 평면에서 V/f 곡선 아래(안전 영역)를 벗어나는 순간이 없어야 한다.

전환 파형으로 보기

업 트랜지션 타이밍 (V→settle→f)

요청 → VDD가 slew로 상승 → V_SETTLED 어서트 → 그때서야 클럭 주파수를 높임. settling 동안 코어는 여전히 낮은 f로 정상 동작합니다(멈추지 않음).
전환을 깨는 세 가지 사고

Timing fail · di/dt droop · Glitch

① V 안정 전에 f↑
전압이 덜 올라온 상태에서 빠른 클럭을 주면 게이트 지연이 커서 셋업 타이밍 fail → 데이터 깨짐·행. 순서 위반의 직접 결과.

② di/dt droop
전류 요구가 급변하면 V = L·di/dt로 전압이 순간 처짐(droop). 깊은 droop은 일시적 타이밍 마진 잠식 → 간헐 fail.

③ Clock glitch
주파수 전환 중 mux를 그냥 바꾸면 짧은/이상한 펄스 발생 → 플롭이 오동작. 다음 슬라이드의 glitch-free mux로 막는다.

di/dt 완화책: 디커플링 캡, 전류 step을 단계적으로(주파수를 한 번에 안 올리고 ramp), droop detector + 즉시 클럭 스트레치/스로틀(adaptive clocking). 면접에서 "droop 어떻게 대응?"이면 이 세 가지를 답하면 됩니다.

주파수를 안전하게 바꾸는 회로

Glitch-free clock mux

두 클럭 사이를 그냥 mux로 전환하면 짧은 펄스(glitch)가 생깁니다. 그래서 선택을 비동기로 끄고, 각 클럭 도메인에 동기화한 뒤, 새 클럭을 켭니다.

// glitch-free 2-입력 클럭 mux 핵심 아이디어
// 1) 현재 클럭을 '끄는' 신호를 그 클럭의 하강엣지에 래치
// 2) 양쪽 모두 off 확인(겹침 방지)
// 3) 새 클럭 enable을 새 클럭 도메인에 동기화 후 ON
always_ff @(negedge clk0) en0 <= sel_0 & ~en1;
always_ff @(negedge clk1) en1 <= sel_1 & ~en0;
assign clk_out = (clk0 & en0) | (clk1 & en1);
negedge 래치 + 상호배제(en0·en1 동시 1 금지)로 펄스 폭이 깨지지 않게 보장

왜 negedge? 클럭이 0인 구간에서 enable을 바꿔야 출력에 짧은 high 펄스가 안 생긴다. 두 enable의 상호배제로 두 클럭이 겹쳐 OR되는 순간을 없앤다.

단순 clk_out = sel ? clk1 : clk0; ❌ → sel이 클럭 high 중에 바뀌면 truncated pulse. 실제 SoC에선 절대 이렇게 안 짠다.

실리콘 편차를 보정한다

AVS / AVFS · Body Biasing

🎚️ AVS / AVFS

AVS=Adaptive Voltage Scaling, AVFS=…and Frequency. 고정 OPP 전압 대신 칩마다·온도마다 실측해 딱 필요한 만큼만 전압을 준다.

  • 온칩 공정 모니터(PVT/ring-oscillator) 센서로 실제 속도 측정
  • 빠른 칩은 V↓(전력↓), 느린 칩은 V↑(동작 보장)
  • "guardband(여유전압)"를 깎아 전력 절감

🔧 Body Biasing

트랜지스터 바디(well)에 전압을 줘 Vt를 조절.

  • FBB(forward): Vt↓ → 빨라짐(누설↑)
  • RBB(reverse): Vt↑ → 누설↓(느려짐)
  • idle엔 RBB로 누설 잡고, 부스트엔 FBB로 속도

왜 필요한가: 같은 설계라도 공정 편차로 칩마다 속도가 다름(fast/typical/slow corner). 고정 전압은 최악 칩 기준 guardband를 모두에게 강제 → 낭비. AVS는 그 낭비를 칩별로 회수합니다.

검증 엔지니어의 시선

DVFS·전력 시퀀싱을 어떻게 검증하나

🧩 무엇으로

  • UPF(IEEE 1801)로 전력의도 기술 → power-aware 시뮬
  • 전압 노드를 supply set/state로 모델링, level shifter·isolation 자동 체크
  • V/f 전환 시퀀스에 SVA assertion
  • OPP 전환 회귀 + 커버리지로 조합 소진

🎯 무엇을(코너)

  • 순서 위반 금지: f가 V_settled보다 먼저 오르면 fail 단언
  • 모든 OPP↔OPP 전환(up/down) + 연속 전환
  • 전환 중 트래픽 진행(버스가 멈추지 않음)
  • glitch-free mux: 전환 클럭에 truncated pulse 0
  • retention/power-gating과 DVFS 동시 진행
// V_settled 어서트 전엔 고주파 clk_en이 뜨면 안 됨
assert_seq: assert property (@(posedge ref_clk)
   (req_high_freq |-> v_settled throughout clk_high_en[->1]) );
SVA: 고주파 요청 후 clk_high_en이 뜰 때까지 v_settled가 유지돼야 한다(순서 보증)

동적 전력과 누설 전력의 차이와 식은?
동적 전력은 스위칭으로 소모되며 P=α·C·V²·f, V가 제곱으로 들어갑니다. 누설은 클럭이 멈춰도 흐르는 정적 전류로 P=V·I_leak이고, 온도와 낮은 V_t에 민감해 미세공정·고온에서 비중이 커집니다.
성능을 올릴 때 V와 f 중 무엇을 먼저, 왜?
전압을 먼저 올리고 settling을 기다린 뒤 주파수를 올립니다. 높은 f는 높은 V를 요구하는데, V가 덜 오른 상태에서 f를 올리면 게이트 지연이 커져 셋업 타이밍 fail이 납니다. 내릴 때는 반대로 f를 먼저 낮춘 뒤 V를 낮춥니다 — 항상 안전한 (높은 V·낮은 f) 쪽으로 먼저 갑니다.
AVS가 무엇이고 왜 쓰나요? 검증은요?
AVS는 고정 OPP 전압 대신 온칩 공정·온도 센서로 실측해 칩마다 딱 필요한 전압만 주는 기법입니다. 최악 칩 기준 guardband를 칩별로 회수해 전력을 줄입니다. 검증은 UPF로 전력의도를 기술하고, V/f 전환 순서를 SVA로 단언하며, di/dt droop·glitch-free mux·OPP 전환 조합을 커버리지로 소진합니다.
핵심 요약

DVFS 정밀 — 한 손에

  • Pdyn=α·C·V²·f(V는 제곱), Pleak=V·Ileak(온도·V_t 민감)
  • 에너지/op의 핵심은 V; race-to-idle은 누설 비율로 판단
  • OPP=(V,f) 보장점 테이블, governor(schedutil)가 선택
  • PMIC를 I2C/PMBus/SPMI로 제어, settling 대기 필수
  • 올릴 때 V→f, 내릴 때 f→V(안전 영역 유지)
  • di/dt droop·glitch-free mux·AVS/body bias

"DVFS는 (V,f) OPP 위를 움직여 전력을 줄이되, 전환 순서(올릴 땐 V먼저, 내릴 땐 f먼저)로 타이밍을 지키고, glitch-free mux와 droop 대응으로 안전하게 바꿉니다. 검증은 UPF + 시퀀싱 assertion으로 합니다."
