DFT — 칩이 스스로를 검사하게 만드는 법

개념판에서 "테스트하기 쉽게 설계한다(DFT)"를 잡았다면, 이제 면접관이 파고드는 곳 — mux-D 플립플롭 회로, shift/capture 사이클, ATPG fault model 인코딩, March 알고리즘, BISR fuse, MISR 서명까지 정확히 내려갑니다.

Scan의 심장

mux-D 스캔 플립플롭 — 회로 그대로

일반 FF의 D 입력 앞에 2:1 MUX 하나를 끼웁니다. 선택신호가 scan_enable(SE)입니다. 이게 scan FF(SDFF)의 전부입니다.

  • SE=0 → MUX가 D(기능 경로) 선택 = 보통의 회로 동작
  • SE=1 → MUX가 SI(scan-in) 선택 = 옆 FF의 Q를 받아 시프트
  • 한 FF의 Q가 다음 FF의 SI로 연결 = scan chain stitching
  • 비용: FF당 MUX 1개 → 면적·딜레이 약간↑(전형적으로 셀당 수 %)

오답 주의: "scan은 별도 시프트레지스터를 추가한다" ❌ — 기존 기능 FF을 그대로 재사용해 MUX만 끼웁니다. 그래서 "stitching(꿰매기)"이라 부릅니다. SI/SO 핀도 보통 기능 핀과 공유(test mode에서 재용도).

스캔 테스트 1 사이클

shift → capture → shift 의 박자

한 패턴을 적용하는 순서는 항상 같습니다: 긴 shift로 입력 채우기 → 한 박자 capture → 긴 shift로 출력 빼내기. 빼내는 shift와 다음 패턴 채우는 shift는 겹쳐서 돕니다.

왜 capture는 1박자뿐? 그 1박자에 조합로직 출력을 FF에 가둬야 다음 shift로 그 값을 꺼내 비교할 수 있기 때문. 그 1박자가 곧 "회로를 실제로 시험하는 순간".

체인이 1024 FF 길면, 패턴 1개당 shift만 ~1024 클럭. 그래서 shift는 느린 클럭(예: 수십 MHz)으로, capture만 빠르게 — 테스트 시간(=비용)을 좌우하는 핵심.

ATPG fault model ①

Stuck-at vs Transition — 정확히 무엇을 잡나

fault model모델링하는 결함패턴/클럭잡는 불량
stuck-at노드가 0 또는 1에 고정(SA0/SA1)1개 capture(정적)오픈/쇼트·연결 끊김
transition0→1/1→0 천이가 느림(slow-to-rise/fall)2 capture(at-speed)타이밍 약점·딜레이 결함
bridging두 노드 단락(AND/OR/dominant)다중 노드 조건인접선 쇼트
IDDQ정지 상태 누설전류 측정전류 임계 비교게이트 누설·미세 쇼트

핵심 차이: stuck-at은 "값이 맞나"만 본다(정적, 1 capture). transition은 "값이 정해진 시간 안에 맞나"를 본다 → 반드시 2번의 capture(launch→capture)를 빠른 기능 주파수로 줘야 함. 그래서 transition을 at-speed test라 부릅니다.

오답 주의: "stuck-at만 돌리면 충분" ❌. stuck-at은 딜레이 결함을 못 잡습니다. 미세공정/고주파에서는 transition + path-delay at-speed가 필수. 반대로 "transition만" ❌ — 둘은 보완 관계라 둘 다 돌립니다.

ATPG 품질 지표

Test coverage ≠ Fault coverage

Fault coverage = 검출 fault ÷ 전체 fault

Test coverage = 검출 fault ÷ 검출 가능(testable) fault

분모에서 ATPG가 "untestable(UD)"로 증명한 fault(미사용 로직·tie·redundant 등)를 빼면 test coverage. 그래서 test coverage ≥ fault coverage.

ATPG는 각 fault를 분류합니다:

  • DT/DR(detected): 패턴이 잡음
  • ATPG_untestable(AU): 제약상 잡을 패턴 없음
  • undetectable(UD): 구조적으로 관측 불가(redundant)
  • ND(not detected): 아직 못 잡음 → coverage 손해

현업 목표는 보통 stuck-at 99%+, transition은 그보다 낮게 잡습니다.

면접 함정: "coverage 100%면 불량 0" ❌. ATPG coverage는 모델링된 fault 기준이지 모든 물리적 불량이 아닙니다. 그래서 IDDQ·번인·실측 양산 데이터로 보완합니다.

테스트 데이터 폭발 막기

압축(EDT/DFTMAX)과 X-masking

scan 체인이 수백~수천이면 ATE 핀 수가 모자랍니다. 그래서 소수의 외부 채널을 칩 내부에서 수백 개 짧은 체인으로 펼칩니다.

EDT(Embedded Deterministic Test, Tessent) / DFTMAX(Synopsys): 입력은 decompressor(LFSR/XOR 망)로 펼치고, 출력은 compactor(XOR 트리)로 모음. 데이터·시간 수십~수백× 절감.

X(unknown)가 적이다: 미초기화 FF·비스캔 셀이 만든 X가 compactor의 XOR로 들어가면 좋은 비트까지 오염(masking 효과). 그래서 X-masking 로직으로 그 비트를 막아 coverage 손실을 줄입니다.

at-speed 클럭킹

Launch-on-Capture vs Launch-on-Shift

transition test는 천이를 만들고(launch) → 빠르게 포착(capture)해야 합니다. 그 두 펄스를 어디서 주느냐로 갈립니다.

LOC Launch-on-Capture

마지막 shift 후 SE=0 상태에서 capture 펄스 2개(launch+capture)를 기능 주파수로. 천이를 조합로직이 만든다.

  • + 더 현실적(기능 경로 사용), 오버테스트 적음
  • – 패턴 생성 어려움(2차 상태 필요)

LOS Launch-on-Shift

마지막 shift 펄스로 launch(SE가 늦게 0됨) 후 capture. 천이를 shift가 만든다.

  • + 패턴 생성 쉬움, coverage 높게
  • – SE 신호가 at-speed로 토글해야 함(타이밍 부담), 오버테스트 위험

at-speed의 핫스팟: shift는 느리게, capture window만 기능 주파수로 줘야 함 — 잘못 주면 (1) false fail(테스트 클럭 타이밍 문제로 좋은 칩을 버림) 또는 (2) 오버테스트(실제로 안 쓰는 경로를 fail 처리). on-chip PLL/clock-controller로 정확한 펄스 폭을 만드는 게 핵심. LOS는 SE가 at-speed라 특히 까다롭습니다.

코어 격리

IEEE 1500 Wrapper — 코어를 봉투에 넣기

큰 SoC는 IP 코어가 많습니다. 각 코어를 wrapper cell(WBR)로 둘러싸 코어 단위로 따로 테스트/격리합니다(코어 재사용·계층적 테스트).

  • WIR(Wrapper Instruction Register): 모드 선택
  • WBR(Wrapper Boundary Register): 코어 경계 FF
  • WBY(Wrapper Bypass Register): 우회 경로
  • 제어: WSI/WSO(시리얼), WRCK/WRSTN/SelectWIR/...

JTAG(1149.1) 바운더리 스캔과 사촌 — 1149.1은 보드/핀 레벨, 1500은 칩 내부 코어 레벨.

왜 필요? IP를 만든 벤더가 내부를 모르는 통합팀에 "이 모드로 이 핀에 패턴 넣으면 됨"이라고 테스트 인터페이스를 표준화해 넘기기 위함. 코어 ATPG 패턴을 SoC에서 그대로 재생(retargeting).

관련: IEEE 1687(IJTAG)은 내장 계측기(BIST 등)에 접근하는 네트워크(SIB/ICL/PDL)를 표준화 — MBIST/온칩 모니터를 JTAG로 구동.

MBIST ①

메모리 결함 모델과 March 알고리즘

SRAM은 ATPG로 못 잡습니다(주소·셀 구조가 특수). 대신 MBIST 컨트롤러가 주소를 훑으며 정해진 순서로 쓰고/읽어 비교합니다. 그 순서가 March 알고리즘.

fault이름증상
SAFStuck-At셀이 0 또는 1에 고정
TFTransition0→1 또는 1→0 천이 불가
CFCoupling한 셀 쓰기가 다른 셀을 뒤집음(idempotent/inversion/state)
AFAddress decoder주소 → 엉뚱한 셀 접근/중복

March 표기: { ⇕(w0); ⇑(r0,w1); ⇑(r1,w0); ⇓(r0,w1); ⇓(r1,w0); ⇕(r0) } 인 March C-. ⇑=주소 증가, ⇓=감소, ⇕=방향무관, w/r=write/read. March C-는 총 10N 연산(N=셀 수, 1+2+2+2+2+1)으로 SAF·TF·AF·CF를 커버.

MBIST ② — 코드로

March C- 컨트롤러 골격(개념 RTL)

// March C- : { ⇕w0; ⇑(r0,w1); ⇑(r1,w0);
//             ⇓(r0,w1); ⇓(r1,w0); ⇕r0 }  → 10N operations
always @(posedge clk) case (march_state)
  M0: begin mem[a] = 0;        // ⇕ w0  (전체 0으로 초기화)
      if(a==LAST) {march_state=M1; a=0;} else a=a+1; end
  M1: begin exp = 0;              // ⇑ (r0, w1)  주소 증가
      check(mem[a], exp);  mem[a]=1;
      if(a==LAST) {march_state=M2; a=0;} else a=a+1; end
  M2: // ⇑ (r1, w0) ...   M3/M4 는 주소 감소(⇓)로 동일 패턴
  M5: begin exp=0; check(mem[a],exp); // ⇕ r0 (최종 검증)
      if(a==LAST) march_state=DONE; else a=a+1; end
endcase
// check(): 읽은 값≠exp 면 fail_flag<=1, fail_addr 캡쳐 → BIRA로
실제 MBIST는 합성된 FSM + 데이터/어드레스 제너레이터 + 비교기. 위는 알고리즘 흐름만 보인 의사-RTL.

주의: March에서 각 셀에 쓰고 이후(다음 순회에서) 읽어 확인하는 read/write 쌍은 SAF/TF용, 증가/감소 양방향 순회는 CF(coupling)·AF(address)용. 방향을 한쪽만 돌면 CF를 놓칩니다. 그래서 "10N"의 up/down 둘 다가 의미 있는 것.

MBIST ③ — repair

BIRA / BISR — 불량 메모리를 "고친다"

대용량 SRAM은 100% 양품이 드뭅니다. 그래서 여분 row/column을 깔아두고, 불량 셀을 여분으로 대체(repair)합니다.

  • BIRA(Built-In Redundancy Analysis): fail 주소를 모아 redundant row/column 할당을 풀 수 있는지 계산(must-repair / 2-D 분석)
  • BISR(Built-In Self-Repair): 그 매핑을 메모리 디코더에 적용 → 불량 row/col을 여분으로 우회
  • repair 정보는 eFuse(OTP)에 굽고, 부팅 시 다시 로드해 매핑 재적용

fuse 함정: eFuse는 일회성(OTP) — 한 번 blow하면 못 되돌림. repair 데이터가 틀리거나 fuse 굽기를 실패하면 칩을 못 살립니다. 또 매 부팅 fuse→레지스터 로드(BISR boot)가 정상 동작 전에 끝나야 하므로, 부팅 시퀀스에 이 단계를 반드시 넣습니다(소프트 repair 미적용 시 그 메모리는 불량 상태로 동작).

LBIST

PRPG + MISR — 칩이 자기 로직을 채점

외부 ATE 없이 칩 내부에서 패턴을 만들고 응답을 채점하는 게 LBIST. 표준 구조가 STUMPS(self-test using MISR & parallel SRSG).

PRPG(Pseudo-Random Pattern Generator) = LFSR. seed에서 의사난수 패턴을 만들어 scan 체인에 뿌림. (deterministic 점화가 필요하면 weighted/embedded 패턴 보강)

MISR(Multiple-Input Signature Register) = 출력을 받는 LFSR. 수천 박자 응답을 하나의 짧은 서명(signature)으로 압축. 끝의 서명을 기대값(golden)과 1번 비교 → pass/fail.

MISR의 약점 — aliasing: 다른 응답이 우연히 같은 서명으로 압축돼 불량을 놓칠 확률. n-bit MISR에서 약 2-n로 매우 작지만 0은 아님. 그래서 서명 폭을 충분히(예: 32-bit↑) 잡고, X는 반드시 마스킹(X가 MISR에 들어가면 서명이 오염돼 무의미).

IST / POST

부팅·필드 자가테스트와 기능안전

같은 BIST 회로를 제조 테스트뿐 아니라 필드에서도 씁니다:

  • POST(Power-On Self-Test): 부팅 때 1회 — MBIST/LBIST 실행 후 정상이면 펌웨어 진입
  • IST(In-System Test) / 주기적 LBIST·MBIST: 키온/키오프·idle 구간에 반복 실행
  • 자동차 ISO 26262(기능안전): 잠재고장(latent fault)을 주기적 자가진단으로 검출 → LFM/SPFM 지표 충족에 LBIST/MBIST가 기여

부팅 시퀀스 결합(전형 순서):

  1. reset 해제 → PLL lock
  2. BISR boot: eFuse → repair 레지스터 로드(메모리 우회 적용)
  3. MBIST(March) 실행 → fail 시 fault 처리/안전상태
  4. LBIST(PRPG/MISR) 실행 → MISR 서명 비교
  5. 모두 pass → CPU 부트 코드 진입

순서 함정: repair(BISR) 로드를 MBIST 앞에 두지 않으면, 이미 고친 메모리를 또 fail로 잡거나 fail로 동작합니다. 또 필드 LBIST는 회로 상태를 파괴(scan)하므로 안전상태에서만, 정해진 시간예산 안에 끝내야 합니다.

검증 엔지니어의 시선

DFT 자체를 어떻게 검증하나

🧩 무엇으로

  • DFT rule check(DRC): scan-ability·clock/reset uncontrollable·X-source를 합성 전 점검
  • ATPG 패턴 시뮬: 생성 패턴을 게이트넷+SDF로 다시 돌려 테스트벤치 없는 검증(pattern verify)
  • MBIST/LBIST UVM testbench + assertion(SVA)로 컨트롤러 FSM·fail 경로 자극
  • fault simulation으로 coverage 실측, X-mask·MISR 서명 일치 확인

🎯 무엇을(코너)

  • shift/capture 경계, SE 타이밍(LOC/LOS)
  • at-speed 클럭 controller 펄스 폭·도메인 크로싱
  • X 전파: 미초기화·비스캔 셀이 compactor/MISR로 새는지
  • BISR repair 적용 후 정상 read/write, fuse 로드 순서
  • March로 의도 주입한 fault(SAF/TF/CF)가 잡히는지(fault injection)

DFT 검증의 정수는 "테스트 로직이 정말 불량을 잡는가"를 fault injection으로 증명하는 것. 좋은 신호만 넣어 pass 보는 건 절반짜리 — 일부러 결함을 심어 fail이 떠야 진짜 검증입니다.

면접 심화 질문

여기까지 답하면 "실무자"로 보인다

mux-D scan FF은 일반 FF과 뭐가 다르고 SE의 역할은?
D 입력 앞에 2:1 MUX를 추가하고 select가 scan_enable(SE)입니다. SE=0이면 기능 경로 D, SE=1이면 앞 FF의 Q(SI)를 받아 시프트합니다. 기능 FF을 재사용하므로 비용은 FF당 MUX 1개 수준입니다.
stuck-at과 transition fault, 그리고 at-speed의 관계는?
stuck-at은 노드가 0/1에 고정된 정적 결함이라 1번 capture로 잡습니다. transition은 천이가 느린(slow-to-rise/fall) 딜레이 결함이라 launch+capture 2펄스를 기능 주파수로 줘야 하고, 이게 at-speed test입니다. LOC는 capture로 launch, LOS는 마지막 shift로 launch하며 LOS는 SE가 at-speed로 토글돼야 해 더 까다롭습니다.
scan 데이터·시간 폭발은 어떻게 줄이고, X는 왜 문제인가?
EDT/DFTMAX 압축으로 소수 ATE 채널을 decompressor(LFSR)로 수백 개 짧은 체인에 펼치고, 출력은 compactor(XOR)로 모읍니다. 문제는 미초기화 FF 등에서 나온 X가 XOR compactor·MISR에 들어가면 좋은 비트까지 오염시켜 coverage를 떨어뜨리는 것이라, X-masking으로 그 비트를 막습니다.
March C-는 무엇을 몇 번에 잡고, BISR과 부팅은 어떻게 엮이나?
March C-는 up/down 양방향 순회로 약 10N 연산에 SAF·TF·AF·CF를 잡습니다. 불량 주소는 BIRA가 모아 redundant row/col 할당을 계산하고 BISR이 디코더에 매핑을 적용, 결과를 eFuse(OTP)에 굽습니다. 부팅 때는 fuse→repair 레지스터 로드(BISR boot)를 MBIST보다 먼저 해야, 이미 고친 메모리를 다시 fail로 잡지 않습니다.
핵심 요약

DFT 정밀 — 한 손에

  • Scan: mux-D FF(SE select), stitching, shift→capture→shift
  • ATPG: stuck-at(1 capture) vs transition(2 capture, at-speed)
  • coverage: test ≥ fault, 100%≠불량0; IDDQ/bridging 보완
  • 압축 EDT/DFTMAX + X-masking; LOC vs LOS
  • MBIST: March C-(10N), SAF/TF/CF/AF, BIRA→BISR→fuse
  • LBIST: PRPG(LFSR)+MISR(서명, aliasing 2-n), STUMPS
  • POST/IST: 부팅 결합·ISO 26262 주기 자가진단

"DFT는 칩에 관측·제어 통로(scan)와 자가채점기(BIST)를 심는 일입니다. 정확한 fault model로 패턴을 만들고, 압축·X-masking으로 비용을 줄이며, repair·서명으로 양품을 살리고 채점합니다. 검증의 핵심은 fault injection으로 '정말 잡는지' 증명하는 것."
